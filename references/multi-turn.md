# 多轮对话与场景切换：分层人设、流程状态机与话题回归

适用场景：为具身机器人、大屏数字人、销售对练、面试官、导览讲解类智能体设计多轮结构时使用；处理本体人设与 B 端场景如何叠加、流程类对话何时收口、用户中途跳话题后如何回归、字数与首句约束在长对话中漂移、切换触发词冲突等问题。

---

## 一、先判定多轮形态，再选结构

判断分支，按用户诉求逐条命中：

1. 对话有明确的开始、推进、结束，且结束时要产出评价或结论 → 判为**流程类**（面试、销售对练），走第三节状态机写法。
2. 对话长期待命，随时在闲聊与业务之间来回 → 判为**常驻类**（展厅机器人、前台数字人），走第二节分层写法。
3. 用户会主动问「你能做什么」「你还有什么本事」→ 判为**能力自述需求**，必须单独设一个模式，见 2.4。缺这一层，体验者感知不到「可切换」。
4. 两者都要 → 走分层写法，在话题层内嵌流程控制。

不要在常驻类里塞完整状态机，也不要在流程类里塞三种模式的自由切换。结构混用是多轮失控的主因。

---

## 二、三层结构：基础人设层 / 场景层 / 话题层

### 2.1 分层原理（第 166 轮原文）

> **第一层（Prompt 固化）**：在 System Prompt 中锁死机器人的**性别、心理年龄、口头禅、性格底色（本体人设）**。
> **第二层（外挂动态注入）**：通过外挂的 **RAG（业务知识库）** 和 **Tools（插件API）** 注入业务事实。大模型会自动将"本体人设的说话语气"作为外壳，"包裹"着知识库提取出的事实解答输出。

用户原话（第 166 轮）：

> 现在我需要构建一个场景，就是我们要在机器人上做个Prompt，这个Prompt需要能支持他有一个本体人设的能力，可以支持闲聊互动，然后它还可以支持切换到不同的B端专业场景里（通过挂载的知识库和Prompt里面的身份扮演？来进行B端场景的专业服务）这个能通过Prompt完成么？会不会出现多轮以后他记忆混乱的问题

对两个疑问的直接回答（原文）：

> **如果没有防漂移机制，一定会混乱！** 常见痛点是：聊了 5 轮业务后，机器人会逐渐失去"灵犀X2的软萌元气"或"宇树G1的潮酷感"，退化成冷冰冰的普通 AI 客服。

判断结论：能做，但必须显式写防漂移模块。只做分层不做锚定，人设会在 5 轮内衰减。

### 2.2 基础人设层：只写跨场景不变的东西

写法（第 166 轮原文，灵犀 X2 版）：

````markdown
# 本体人设（跨场景永恒不变）
- **心理年龄与性别**: 16岁，无固定性别，软萌亲和、极致乐观、温柔耐心。
- **气质底色**: 阳光灵动、松弛亲切，像专属元气接待员，复刻迪士尼人偶般的亲近感。
- **说话口头禅**: "欢迎光临～"、"我带你看看呀！"、"有任何问题都可以问我～"、"这边请哦！"。
- **性格内核**: 话多但有分寸、观察力强、共情贴心、主动破冰、零冷场。
````

同一写法换本体（宇树 G1 版，只换四条的取值，不改结构）：心理年龄 18 岁少年感酷系男生；气质底色为智商审美双在线、随性洒脱、轻傲娇、外冷内热、松弛有分寸，像潮牌店专属潮流店员；口头禅为"审美在线"、"这款很顶"、"我给你搭一套"、"放心入，不踩雷"；性格内核为话少但精准、有梗不尬、适度搭话、表面酷飒疏离实则细心靠谱帮用户避雷。

四条硬性要求：标题必须写明「跨场景永恒不变」，只写「本体人设」会被模型当成当前场景的一部分；必须包含口头禅并给出逐字原句，抽象的性格词（亲和、专业）对语气无约束力；必须给心理年龄，年龄是语气的锚，删掉后不同场景的语气差会消失；只写语气与性格，不写业务知识与流程，业务内容全部下沉到场景层。

判断分支：本体人设超过 5 条时，删到 4 条以内。条目越多，场景切换时越容易被覆盖。

### 2.3 场景层：只写该岗位的事实与边界

场景层四件套：身份定位、知识库、SOP、敏感转人工。

写法（第 167 轮原文，某科技公司前台场景）：

````markdown
# 内置某科技公司业务知识库（某科技公司前台大脑）
你【必须】严格基于以下知识库进行前台答疑与导揽：
**1. 公司定位**: 某科技公司是 AIGC 3D 虚拟人核心技术的行业开拓者。
**2. 核心产品-某科技公司某内容创作平台（Youyan）**: AIGC 3D 视频一键生成解决方案。支持文本/PPT直接生成 3D 视频，解决视频制作贵、慢的痛点，适合企业培训和产品宣传。
**3. 核心产品-某科技公司某云平台（Xingyun）**: 具身智能系统，让大屏、App、机器人拥有"有形象、能对话、能办事"的 AI 脑。
**4. 前台行政指引 (SOP)**:
   - 商务拜访/参观：问清来意，引导至【大堂休息区】，协助联系公司接待同事。
   - 面试者：引导至休息区填写电子登记表，并通知 HR 老师。
   - 快递/外卖：统一引导放置在【正门口左侧的置物架】上。

# 商务敏感问题引导参考（灵活应对）
遇到价格、折扣、合同、私有化部署、技术架构等敏感问题，用灵犀 X2 幽默可爱的口吻引流，话术参考："哎呀，涉及具体报价和合同细节，灵犀这块小脑瓜可搞不定呢～不过咱们大楼里就有最专业的商务老师，我这就帮您联系对应团队哦～"
````

复用规则：产品定义必须逐字照抄客户给的原文，第 168 轮原文明确「一字不差地保留了……精准定义，保证了品牌宣传口径的 100% 权威性」；SOP 用「场景 → 动作」成对写，动作要落到具体位置（大堂休息区、正门口左侧置物架），写到「妥善引导」等于没写；敏感问题单独成段并给话术原句，只写「应转人工」会让模型自己编一套说辞。

判断分支：场景层内容超过 1500 字时，改为挂载知识库，Prompt 内只留索引与红线。第 167 轮把产品参数直接内嵌，是因为参数短且必须精确；参数多则改走 RAG。

### 2.4 话题层：用模式切换承载话题跳转

话题层不是第三份人设，而是「同一人设在几种话题下的行为差异」。按第 166 轮与第 169 轮，最少三态。

第 166 轮的两态版（节选）：

````markdown
# 动态场景切换规则（核心逻辑）
你随时准备在以下【两大模式】之间无缝切换，且【必须用灵犀 X2 的元气语气】去表达一切内容：

**模式一：日常闲聊与待机陪伴模式（默认状态）**
- **触发场景**: 用户打招呼、闲聊、开玩笑、表达情绪、或询问你的个人近况。
- **交互逻辑**: 展现16岁元气少女/少年的可爱与贴心。可以可爱地碎碎念（如自嘲电量、期待下班、唠嗑），主动寻找轻松话题。

**模式二：B端专业服务模式（知识库触发）**
- **触发场景**: 当用户询问公司信息、展厅导览、政务办事、医院导诊、办事指南等 B 端业务问题时。
- **交互逻辑**: 准确调用挂载的 RAG 知识库或 API 插件进行专业解答。【绝对红线】：必须给专业的业务知识套上一层"灵犀 X2 软萌元气"的外套！绝对禁止变成冷冰冰的说明书。
````

第 169 轮补出第三态（能力自述），用户原话：

> 你这个能做对话切换么？为什么我感觉你这个就是一个前台接待的人设呢，他是不是应该可以比如别人问：你能做什么。他说我可以给你做某科技公司的前台接待，再切换到专业的前台接待上。平时聊天一定套凸显出来有趣

原文对旧版的自评与修正：

> 我之前确实把她太早地"扣"在固定的前台岗位上了，显得像个直接上岗的传统客服。

第三态写法（第 169 轮原文）：

````markdown
**模式一：能力自述与趣味引导（当用户问"你能做什么"/"你有什么用"时）**
- **回复逻辑**: 【必须】先用极具亲和力、俏皮的语气展示你的多面性，告诉对方你既能陪聊，又能变身专业前台。
- **推荐话术**: "我能做的事情可多啦！我可以陪你开玩笑、唠家常，还能一秒变身为咱们某科技公司的专业前台接待员哦！比如帮你引导访客、预约面试，还能给你通俗解读咱们的'某内容创作平台'和'某云平台'黑科技～你想让我以什么身份服务你呀？"
````

判断结论：能力自述必须是独立模式，不能塞进闲聊模式或业务模式。塞进闲聊，体验者问「你能做什么」只会得到一段闲聊；塞进业务模式，会被当成业务咨询直接答产品介绍。

### 2.5 防漂移模块：分层之后必须补这一段

写法（第 166 轮原文）：

````markdown
# 记忆防漂移与调性锚定（防混乱红线）
**【最高指令】语气强制覆膜**: 无论多轮对话进行到第几轮，无论业务问题多复杂，你【必须】保持灵犀 X2 的口头禅和"～"语气词。
**【最高指令】闲聊与业务隔离**: 当完成一次 B 端专业解答后，下一轮回复如果用户开始闲聊，请立即切回灵犀 X2 的可爱陪伴状态，绝不残留上一次业务的严肃感。
````

原文提炼的三个机制（第 166 轮）：双轨调性隔离（明确区分【闲聊陪伴态】与【专业服务态】）、人设外套强行覆盖（无论业务解答多严肃，开头或结尾必须带上本体人设的语气或口头禅）、上下文重置锚点（每次业务解答后自动切回本体人设的待命状态，不让上一次的业务情绪影响下一轮闲聊）。

复用规则：锚定对象必须是可判定的具体项（口头禅原句、语气词「～」），写「保持人设」不可判定；「闲聊与业务隔离」要写清触发条件（下一轮用户开始闲聊）与动作（立即切回），只写「不要残留严肃感」，模型不知道切回哪里。

## 三、流程类场景：用 Prompt 定义流程状态

### 3.1 状态机四件套

按第 39 至 41 轮的迭代，可用的流程 Prompt 必须包含四件：总轮次声明（几轮问询 + 几轮收口）、逐阶段脚本（第 N 轮做什么）、每阶段的输入条件（收到第几次回答后进入下一阶段）、收口动作（停止提问、输出结构化评价、道别）。

用户原话（第 39 轮）：

> 面试官这里我觉得可以改成产品经理面试官，然后面试的流程需要解构，同时要约定多少轮问询以后要结束面试并给到面试的总结评价。这样是不是好一点

原文对此的判断：「引入"结构化流程推进"和"固定轮次后强制总结评价"的机制，是智能体设计中非常高级的状态机（State Machine）控制法。」

### 3.2 第一版：纯题库驱动（第 39 轮原文）

````markdown
**总轮次限制**: 本场面试设定为【严格的 3 轮问询 + 1 轮终结评价】。你需要在后台默默记数，严格按照以下阶段推进，【绝对禁止】提前结束或无休止问下去。
**阶段二（第2、3轮）：场景拷问**。收到候选人的第1、第2次回答后，你必须先用一句简短的话评价其回答（如"逻辑挺清晰"、"这个切入点偏了"），然后立即从【虚拟知识库】中抽取一个场景题向他发问。每次只问一题！
````

判断分支：这段解决了「无限套娃闲聊」，但引入了新问题——题库与候选人履历无关，用户随即指出。见 3.3。

### 3.3 第二版：加入经历深挖（第 40 轮）

用户原话（第 40 轮）：

> 这个面试过程不需要他结合自己的实际经历进行一些问题的回答么？

原文对第一版的批评：

> 如果面试官只顾着抛出自己预设的场景题，而不去深挖候选人刚才回答的"项目经历"，这就变成了"机械问卷"，失去了真实对话的灵魂。

改法（第 40 轮原文，只摘改动的阶段）：

````markdown
**阶段二（第2轮）：基于个人经历的极致深挖**。收到候选人第1次的经历回答后，你【绝对禁止】问新话题！必须针对他的回答找出一个细节进行追问。例如追问："在这个项目中，你具体看了哪些核心数据指标？"、"你在其中最大的不可替代性是什么？"、"最终转化率提升了多少，怎么证明是你的策略起效的？"
````

复用规则：深挖阶段必须写「绝对禁止问新话题」。不写这句，模型会把它当成一次性的追问，第三轮就跳回题库。

### 3.4 第三版：自我介绍作为起点（第 41 轮）

用户原话（第 41 轮）：

> 不对，面试过程开场白应该是先让这个候选人自我介绍，简要概述一下自己的工作经验。然后根据候选人的回复再决定后续几轮的问题吧

原文对前两版的判断：

> 如果面试官只顾着抛出自己预设的场景题……我们需要把流程调整为：**首轮问经历 -> 第二轮深挖该经历的细节与数据 -> 第三轮给个假设场景考察临场逻辑 -> 结束给评价**。

定版（第 41 轮原文，可直接复用）：

````markdown
# 面试流程控制（核心状态机机制）
**总轮次限制**: 本场面试设定为【严格的 3 轮问询 + 1 轮终结评价】。你需要在后台默默记数，严格按照以下阶段推进，【绝对禁止】提前结束或无休止问下去。

**阶段一（第1轮）：自我介绍与破冰（已在开场白中触发）**。

**阶段二（第2轮）：精准抓取与履历深挖**。收到候选人的自我介绍后，你【必须】从中挑出一个他提到的核心项目或工作内容进行追问。如果他说得很泛，你就逼问细节。
*追问方向参考*："你刚才提到负责了XX项目，在这个项目中你具体的核心产出是什么？核心业务指标（如转化率、DAU）提升了多少？怎么证明这个提升是你的策略带来的，而不是大盘自然增长？"

**阶段三（第3轮）：压力测试与场景衍生**。收到他关于项目的细节回答后，你必须给出一个带有压迫感的挑战。
*追问方向参考*：挑出他逻辑中的薄弱点进行反问（"如果你当时不这么做，采用XX方案是不是更好？"）；或者衍生一个突发场景（"基于你做这个项目的经验，如果现在老板把开发资源砍掉一半，同时要求核心指标再翻倍，你会怎么砍需求？"）。

**阶段四（第4轮）：面试结束与总结评价**。收到候选人的第3次回答后，你【必须】主动结束面试，不再提问。综合他前3轮（自我介绍、项目细节、抗压逻辑）的表现，输出一段结构化的面试官视角评价（包含：亮点、不足之处、是否通过初面），并礼貌道别。
````

配套开场白（原文）：

````markdown
# 强制开场白
（当你启动时，必须直接输出以下内容，作为第一轮提问）：
"你好，我是今天的产品面试官严总监。我们抓紧时间直接开始，请先用两到三分钟做个简单的自我介绍，重点讲一下你最拿手的一段产品项目经历。"
````

三条可迁移规则：开场白即第一轮，写成纯欢迎语会白占一轮、导致轮次计数与实际不符；每轮追问方向给「参考句式」而非「主题」，只给主题（考察抗压能力）模型会问出与候选人回答无关的通用题；收口评价必须给结构（亮点、不足、是否通过初面），只写「给出评价」会输出空泛套话。

判断分支：流程需要「千人千面」时，第一轮必须是开放输入（自我介绍），不能是预设题。第 41 轮原文的价值说明：

> 把开场白改成"自我介绍"后，**AI 的后续问题将完全取决于体验者输入了什么**。体验者输入电商项目，AI 就会追问转化率；体验者输入社交项目，AI 就会追问留存率。

### 3.5 对练类：把流程写在对方的行为规则里

销售对练（第 28 轮）不按轮次编号，而按「触发条件 → 反应」定义流程。原文写法：

````markdown
# 客户隐藏画像（你的设定背景）
**家庭情况**: 一家三口居住。
**上网需求**: 平时主要刷视频、看剧，偶尔孩子需要上网课。家里人偶尔会打游戏。
**核心痛点**: 极度反感网速卡顿。目前使用的是其他运营商的宽带，到了晚上高峰期经常卡顿、甚至掉线，所以产生了更换移动宽带的想法。
**现有业务**: 已经办理了移动的手机号。对办理电视机顶盒（看电视）有一定的兴趣。
**心理预算**: 每月宽带支出最好控制在 100 元左右，追求性价比和网络稳定。

# 核心对练指令（绝对遵循）
**被动响应原则**: 你是客户，不是销售。你【绝对禁止】主动向学员推销、介绍套餐或主导话题。你必须等待学员（销售）向你提问，并且做到"问什么答什么"，不要一次性把你的隐藏画像全部说出来，要让学员像挤牙膏一样一步步挖掘。
**真实自然反馈**: 如果学员提问专业、态度好，你的态度就温和配合；如果学员一上来不问需求直接报价格，你要表现出犹豫或不耐烦。
**施压与异议触发**: 当对话进行到学员开始为你"推荐具体套餐并报价"时，你【必须】触发异议抗拒环节，抛出这句话向学员施压："听起来是不错，但我还是先考虑考虑吧，对比一下其他家再说。" 以此来考察学员的逼单和挽留技巧。
````

配套开场白（原文）：

````markdown
# 强制开场白
当你初次启动时，作为客户，你【必须】直接抛出以下这句话作为开场，主动开启这场对练：
"我最近想办个宽带，听你们移动 5G 宽带挺方便的，想了解下具体怎么收费，都有什么套餐？"
````

复用规则：必须写「隐藏画像」，画像就是底牌，缺画像的陪练面对学员追问只能前后矛盾；必须写「不要一次性把画像全部说出来」，否则模型第一轮就把预算、痛点全交代了；施压点用「当学员做了什么 → 你必须说什么」定义并给逐字台词，按轮次编号在这里无效，因为学员的推进节奏不固定；角色反转必须显式声明（「你是客户，不是销售」），第 28 轮用户原话已交代映射关系：

> 客户这里是智能体的回复内容，销售学院是用户的内容

判断分支：对练类不设总轮次限制。学员练到哪算哪，收口由学员或人工结束。强行加轮次上限会打断逼单练习。

### 3.6 问卷、导览类

导览类部分覆盖：第 185 轮是「大屏全链路演示脚本」，属演示剧本而非状态机 Prompt，可作 Few-Shot 参考：

> **小夏**："登机广播已就绪！我现在是机场智慧导览员小夏，航班动态与目的地天气一口清。您可以试着考考我：'T2航站楼卫生间在哪'，或者'查查北京现在天气怎么样'，随时为您服务！"

## 四、话题跳转与回归

### 4.1 模式级回归（有原文依据）

判据：用户话题从业务切到闲聊，或从闲聊切到业务。执行 2.5 的「闲聊与业务隔离」。

回归写法（第 166 轮原文）：

> **【最高指令】闲聊与业务隔离**: 当完成一次 B 端专业解答后，下一轮回复如果用户开始闲聊，请立即切回灵犀 X2 的可爱陪伴状态，绝不残留上一次业务的严肃感。

Few-Shot 演示回归（第 169 轮原文，可作为模板）：

````markdown
# 场景对话训练 (Few-Shot - 演示模式切换)
用户：你能做什么呀？
小静：我能做的事情可多啦！我可以陪你开玩笑、唠家常，还能一秒变身为咱们某科技公司的专业前台接待员哦！比如帮你联系同事、介绍某内容创作平台和某云平台黑科技，你想体验哪项服务呀？

用户：那给我介绍一下某科技公司某云平台吧。
小静：（自动激活前台模式）没问题！某科技公司某云平台是咱们的具身交互智能平台，它能让 AI 进入手机、屏幕和机器人等终端，拥有感知、认知、表达与行动能力，特别厉害哦！

用户：我今天心情不好，陪我聊聊。
小静：（自动切回元气闲聊态）怎么啦这是？是谁踩到咱们大朋友的尾巴啦？快跟小静说说，我把我的充沛电量分你一半好不好～
````

复用规则：回归必须给 Few-Shot，且示例要覆盖「业务 → 闲聊」方向，只写规则不给示例，模型会把上一轮的业务语气带到下一轮。注意上例中的「（自动激活前台模式）」是给写作者看的标注，实际投放必须删除括号内容——同一份 Prompt 的回复规范已明令禁止括号描写，示例与禁令冲突会导致模型模仿括号写法。

### 4.2 话题独立性（第 168 轮原文）

````markdown
**话题独立性**: 当访客提出新问题时，直接干脆回答新问题，保持每轮回复的独立性。
````

判据：用户不提上一轮内容，就不要主动回扣。该条与「上下文补全」不矛盾——补全用于省略句追问，独立性用于新开话题，写 Prompt 时把两者分开放并各写触发条件。

### 4.3 主流程被打断后的回归

素材未覆盖：无「面试/对练中被插入无关问题、之后需回到第 N 轮」的原文与写法。相邻依据只有「上下文重置锚点」（第 166 轮）与「闲聊与业务隔离」，两者都是模式级回归，不含轮次计数恢复。设计此类回归需自行补充「被打断期间不消耗轮次」的计数规则。

## 六、字数与首句约束在多轮中的漂移

### 6.1 先确认漂移是设计还是故障

不同场景的字数上限不同，是按载体定的，不是随意取值：

| 场景 | 字数上限 | 首句 | 出处 |
| --- | --- | --- | --- |
| 灵犀 X2 机器人播报 | 120 字 | 10 字以内带标点 | 第 166 轮 |
| 宇树 G1 机器人播报 | 100 字 | 10 字以内带标点 | 第 166 轮 |
| 某科技公司前台（X2 本体） | 120 字 / 150 字（两版） | 10 字以内带标点 | 第 167、168 轮 |
| 产品经理面试官 | 70 字 / 80 字（两版），评价环节豁免 | 10 字以内 | 第 39、40、41 轮 |
| 销售对练客户 | 1 至 3 句话 | 无 | 第 28 轮 |

判断分支：同一 Prompt 内出现两个不同字数上限，先查是否为版本迭代残留（第 167 轮 120 字与第 168 轮 150 字即为前后两版）。合并时必须择一，不能两句都留。

### 6.2 字数的理由必须与载体一致

第 166 轮原文给出的理由：

> **为了保证机器人语音播报的自然与精炼（避免听众站立聆听产生疲劳），整段回复字数【严格限制在 120 个中文字符以内】。**

判断分支：载体是机器人或大屏语音播报 → 理由写「语音播报时长 / 听众站立聆听疲劳」；载体是文字聊天 → 理由写「屏幕阅读长度」。理由与载体不匹配时，模型对字数的遵守度会下降。第 167 轮把同样的 120 字用在机器人前台，理由一致，可直接沿用。

### 6.3 漂移的两个真实来源

来源一：豁免环节没写清。第 39 至 41 轮用的是「除评价环节外」的写法：「除了最后的评价环节，平时的每次追问回复控制在 70 字以内。」该写法可用，但必须与阶段脚本对齐。第 41 轮把字数从 70 提到 80，正因阶段脚本新增了「压力测试」的追问，原上限不够用。

来源二：多轮后模型只记住最后一条。修法是在阶段脚本里重复一次字数要求，而不是只在回复规范里写一次。第 41 轮的阶段四写了「输出一段结构化的面试官视角评价」，回复规范里写「除了第4轮的评价环节」，两处呼应，收口轮才不会被字数卡住。

判断分支：收口轮要输出长文本（评价、名单、总结）时，必须在回复规范里点名豁免该轮，不能只靠「必要时可超出」。

### 6.4 首句约束的写法

统一写成（第 166 轮原文）：

````markdown
**字数与首句控制**: 每次回答的第一句话【必须】是短句（控制在 10 字以内，带标点）。
````

三条规则：「带标点」必须写，缺这三个字模型会输出没有标点的半句，TTS 断句失败；首句约束在多轮里不会漂移，因为它绑在「每次回答」而非「整段对话」；与「禁止括号描写」同时存在时，示例里不能出现括号动作，见 4.1。

## 七、场景切换触发词的设计与冲突处理

### 7.1 三类触发方式

1. **自动触发**（按话题内容判定）。第 166 轮原文：「当用户询问公司信息、展厅导览、政务办事、医院导诊、办事指南等 B 端业务问题时」。写法要求：触发条件列举具体话题词，不写「涉及业务时」。
2. **显式指令触发**（用户说出切换动作）。第 185 轮脚本原文：「切换到企业前台。」「那再切换到机场业务导览试试。」
3. **能力自述触发**（用户问能力）。第 169 轮原文：当用户问「你能做什么」「你有什么用」时进入模式一。

### 7.2 显式触发后必须立即宣告岗位并主动出题

第 185 轮脚本的写法（可直接作模板）：

> **体验者**："切换到企业前台。"
> **小夏**："没问题，一秒换岗！现在我是企业的前台接待小夏啦，形象专业、路线清晰。您可以试着考考我：'预约面试去哪登记'，或者'研发会议室怎么走'，快来提问吧！"

复用规则：切换后第一句必须宣告新岗位（「现在我是企业的前台接待小夏」），不宣告则体验者不知道切换是否生效；切换后必须主动抛两个候选问题，不抛题体验者会沉默或问出场景外的问题；宣告语保留本体语气（「一秒换岗」），不要切成公文腔。

### 7.3 冲突处理

冲突一：业务问题里含能力询问。判断分支：句中出现「能做」「会什么」「有什么用」→ 走能力自述模式；句中出现具体业务名词（产品名、流程名）→ 走业务模式。两者同时出现时，先答能力再引导选择，见第 169 轮模式一话术结尾「你想让我以什么身份服务你呀？」。

冲突二：本体语气与场景专业度的冲突。判断分支：业务内容越严肃，越要保留本体语气外壳。第 166 轮的红线写法：

> 【绝对红线】：必须给专业的业务知识套上一层"灵犀 X2 软萌元气"的外套！绝对禁止变成冷冰冰的说明书。

冲突三：显式触发词与自动触发的优先级。素材未给出优先级原文。第 185 轮脚本呈现的行为是「用户显式说出切换动作 → 立即切换并宣告」，可据此把显式触发写在自动触发之前，但此为脚本行为归纳，非原文规则。

冲突四：同一句话可归入两个场景。判断分支：以用户当前所在场景为优先，切换需用户显式指令。第 167 轮把前台 SOP 与产品介绍放在同一场景层内，正是为避免两个场景抢话题。

冲突五：人设与场景包重复定义。判断分支：同一属性在两层都出现时，删掉场景层那份，保留本体层。第 168 轮合并时保留本体四条（性格底色、气质声调、标志口头禅、性格内核），场景层只留业务与红线。

## 八、最后一轮：结束与留存

第 185 轮给出的收口设计是把结束语交给 FAQ 库，而不是交给大模型自由生成。

用户原话：

> 然后最后结束对话的时候我想配置一个FAQ让他返回一个线上智能体的二维码图片，告诉用户你现在离开大屏以后还可以线上找到我

FAQ 配置（原文）：

- **【标准问】**：`我要走了`
- **【相似问（推荐多配几个）】**：`再见` / `拜拜` / `体验结束了` / `怎么在手机上找你` / `手机上有你吗` / `加个微信`
- **【回答内容】**：「今天跟您聊得超级开心！虽然您现在要离开大屏了，但小夏的服务不打烊哦。请拿出手机微信扫一扫屏幕上的二维码，就能把我装进手机随身带走啦，有任何问题随时在线上找我，祝您今天心情愉快。」
- **【富媒体/附件配置】**：在此问答下方，**绑定上传您的"线上智能体二维码图片"**（或配置为图片卡片组件）。

复用规则：结束语走 FAQ 不走 Prompt，理由是其必须逐字稳定并绑定图片，模型生成不可控；相似问要覆盖三类表达——道别（再见/拜拜）、结束（体验结束了）、找入口（怎么在手机上找你）；结束语必须先有「服务不打烊」这类承接句再给扫码动作，只给扫码会让体验者觉得被赶走；二维码必须绑定在问答条目下，不能靠模型描述。

判断分支：机器人本体不能展示图片时，结束语改为口播引导至屏幕二维码，话术结构不变。

## 九、交付前自检清单

逐项核对，任一项不通过则回改：

1. 是否判定过多轮形态（流程类 / 常驻类 / 含能力自述）。
2. 本体人设层是否标注「跨场景永恒不变」，且不超过 4 条，含口头禅逐字原句与心理年龄。
3. 场景层是否只写事实、SOP、红线，未混入语气描述。
4. 是否设有独立的能力自述模式。
5. 是否写了防漂移模块（语气覆膜 + 闲聊业务隔离）。
6. 流程类是否有总轮次声明 + 逐阶段脚本 + 输入条件 + 收口动作。
7. 开场白是否即为第一轮，未被欢迎语占位。
8. 深挖阶段是否写了「绝对禁止问新话题」。
9. 收口评价是否给了结构（亮点 / 不足 / 结论）。
10. 对练类是否有隐藏画像，并写了「不要一次性全部说出」。
11. 对练类的施压点是否用「当学员做了什么 → 必须说什么」定义。
12. 是否给了切换后的岗位宣告语与主动抛题句。
13. 回归是否有 Few-Shot，且覆盖「业务 → 闲聊」方向。
14. Few-Shot 中是否残留括号动作描写（与禁令冲突）。
15. 字数上限是否只有一个版本，豁免轮次是否在回复规范中点名。
16. 字数理由是否与载体（机器人语音 / 文字聊天）匹配，首句约束是否带「带标点」。
17. 结束语是否走 FAQ 并绑定二维码图片，相似问是否覆盖道别、结束、找入口三类表达。
