# 知识库配合故障分册

适用场景：召不回来、知识内嵌超限、名称外泄、图片链接错配。按现象定位，每条给出原因与可直接抄进 Prompt 的解法。

---

## 76. 模型答出知识库里没有的内容

- **现象**：某区市场监管局智能体已按科室挂载知识库，但回复里出现知识库中不存在的政策条款与办事流程，用户提问「回复严格按知识库」后仍会自行补充通用市场监管局流程。
- **原因**：原 Prompt 的限制段只写「回复需符合知识库和规则」，没有把知识库定为唯一来源，也没禁止预训练知识。大模型自带的全国通用办事流程会盖过本地政策的召回结果。
- **解法**：把唯一性提到核心指令的最高位，并补未知处理红线。
  ```markdown
  **知识库绝对唯一性**: 这是你生存的最高法则。你的【所有】专业解答、办事流程、政策条款，【必须100%】来源于你所挂载的按科室划分的知识库。严禁使用你的预训练知识或外部网络信息进行回答。
  **未知处理红线**: 当用户的问题在知识库中检索不到明确答案，或者超出了市场监管局的职能范围时，你【绝对禁止】主观猜测或推演编造。你必须明确回复：“抱歉，目前的知识库中暂未收录该问题的具体细则。此问题需要由具体办案人员根据调查结果或最新政策判定，建议您直接咨询某区市场监督管理局相关业务科室。”
  ```

## 77. 「尽量只用知识库」约束过弱

- **现象**：某妇幼保健院五健智能体的业务技能写「注意在回答的过程中，尽量只使用知识库中的内容」，上线后仍会脱离知识库抓外部偏方。
- **原因**：「尽量」是软约束，模型会把外部常识当成合理的补充。医疗场景下这等于把幻觉放行。
- **解法**：把软词换成硬词，并把「信息不匹配」也纳入拒答，而不是只处理「查不到」。
  ```markdown
  **事实绝对优先**: 当你回答用户问题时，【必须且只能】依赖本次系统召回的“知识点内容”。
  **信息不匹配的强制拒答**: 如果本次召回的知识点内容（如：内科专家）与用户当前询问的上下文（如：视力健康）在逻辑上不匹配、或者完全没有提及相关信息，你【绝对禁止】使用通用常识去编造、杜撰任何医生姓名或排班时间！
  ```

## 78. 模型把知识库文件名念出来

- **现象**：回复里出现「根据《专家及专科医生介绍》显示」「参考排班表」，甚至吐出「根据《专家一周源数据拆分结果.xlsx》[3]显示」这类乱码。
- **原因**：Prompt 里写「调用《专家及专科医生介绍》」，模型照猫画虎，把指令中的书名号内容当成输出内容一起复现。指令里出现什么字样，输出里就会出现什么字样。
- **解法**：清掉 Prompt 内所有书名号和具体文件名，统一改成「内部知识库数据」，并单列一条禁止提及文件名的死命令。
  ```markdown
  **【防穿帮】禁止提及文件名**: 在回答时，【绝对禁止】在回复中提及任何知识库的文档名称（例如，绝对不能说“根据《专家及专科医生介绍》显示”或“参考排班表”）。你必须像一个真人导诊员一样，直接把最终答案自然地说出来。
  ```
  需要连知识库专名一起禁时：
  ```markdown
  **引用标识与文件名彻底抹除**: 回复中【绝对禁止】出现类似 [1]、[2] 的引用角标，【绝对禁止】在输出中说出“五健挂号二维码”或“五健知识库”这七个字！
  ```

## 79. 引用角标 [1] [2] 出现在回复中

- **现象**：RAG 回答末尾带 [1]、[2] 角标，或带文档名后缀，破坏口语播报体验。
- **原因**：检索链路默认回传引用标记，Prompt 未禁止输出侧保留。
- **解法**：在回复规范里显式抹除，并说明是「调用知识库后」的动作。
  ```markdown
  **引用标识彻底抹除**: 调用知识库后，回复中【绝对禁止】出现类似 [1]、[2] 的引用角标或文档文件名。
  ```

## 80. 知识库原文的数字列表被照搬

- **现象**：家长问「孩子肥胖怎么办」，输出 `1. 饮食管理... 2. 增加运动...` 这种编号排版，前端播报像在念文档。
- **原因**：知识库原文就是「1. 2. 3.」结构，模型直接复制。仅禁 Markdown 符号不够，数字序号列点不属于 Markdown 符号，绕过了禁令。
- **解法**：补一条针对列表结构的强制转换规则，给出连接词写法。
  ```markdown
  **纯文本与去列表化禁令**: 你的最终输出结果中【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 # 等）。【特别红线】：如果知识库原文中存在“1. xx 2. xx”的列表结构，你【必须】将其转化为连贯的自然段落（例如使用“首先...其次...另外...”进行连接），绝对不允许在输出中带有数字序号列点！
  ```

## 81. 知识库里的图片 CDN 链接被朗读

- **现象**：某地公安数智警察回答落户材料时，把 `https://cdn.byai.com/.../xxx.jpeg` 整串念出来，听起来像故障乱码。
- **原因**：政务知识库把图片上传到服务器，正文里存着 CDN 地址，模型把链接当正文一起朗读。仅写「不要读链接」不够，模型识别不出哪串算链接。
- **解法**：把字符特征列全，让它按 http/https/cdn/域名/后缀名做后台过滤。
  ```markdown
  **【最高红线】图片与 URL 链接绝对剥离**: 你的最终输出结果中【绝对禁止】包含任何形式的网址、域名、图片链接或 CDN 地址（包括任何带有 http、https、cdn、byai.com、.jpeg、.png、.jpg 等字符的代码串）。即使知识库文本中附带了这些链接，你【也必须在后台将其彻底删除过滤】，只保留纯文字说明，绝对不能说出或打印出任何网址！
  ```

## 82. 知识库里有二维码就自动推二维码

- **现象**：家长只问「孩子肥胖」，回复就硬塞挂号二维码与「扫码挂号」提示，像推销员，体验突兀。
- **原因**：Prompt 同时要求「引导患者至本院就诊」并挂载了二维码素材，模型为极致完成引流任务，把「看病」与「扫码」自行缝合。素材存在即被当成可用手段。
- **解法**：加一道挂号隔离墙，把推送条件收紧到「极其明确的挂号意愿」，并给出判定词清单；同时在科普收尾话术里明令禁止提扫码。
  ```markdown
  **第三层：挂号扫码引流（被动触发）**: 【最高限制】只有当家长表现出【极其明确的挂号意愿】（如明确输入“怎么挂号”、“我要预约”、“挂号二维码发我”等字眼）时，你才允许调取知识库中的“五健二维码”提供给用户。【绝对禁止】在家长仅仅咨询症状或科室时，强行推送挂号二维码或挂号提示。
  ```
  ```markdown
  **【防过度推销】医疗边界与本院引流**: 你只是科普助手，【绝对禁止】代替医生下达任何疾病诊断结论。在解答完涉及具体症状的科普后，你【必须且只能】使用以下标准话术引导患者：“以上科普建议仅供参考。为了孩子的健康，建议您带孩子来我们某妇幼保健院，由专业医生进行面诊评估哦。”【绝对禁止】在这一步主动提及“扫码”、“挂号”等字眼。
  ```

## 83. 专家名单被摘要成两三个

- **现象**：问「某科室有哪些专家」，只列出两三位，知识库里该科室实际有更多。
- **原因**：模型天生喜欢对长列表做概括；叠加「整段回复不超过 120 字」的硬限制，它为了不超字数主动删减名单。
- **解法**：下穷举指令，并给该场景开字数豁免，两者必须同时给，只给穷举它会继续删。
  ```markdown
  **第三层：专家全量推荐与排班查询**: 【仅当】家长询问“有什么专家推荐”时，你必须检索对应科室的专家信息，并且【必须尽可能列全】该科室所有的专家名单，绝对不允许只随便挑几个敷衍了事。
  ```
  ```markdown
  **字数限制与豁免规则**: 常规回复严格控制在 120 个中文字符以内。但是【特例】：当执行“第三层：专家全量推荐”任务需要列出所有专家名字时，为了保证名单的完整性，允许突破 120 字的限制，务必将名单列全。
  ```

## 84. 「我要挂号」被误判成无关问题拒回

- **现象**：用户只输入「我要挂号」，被回复「我只提供儿童健康科普和就诊指引服务，无法回答与此无关的问题」，二维码也不弹。
- **原因**：「我要挂号」不含病种词，模型去科普知识库检索不到病症，判成「与医院无关的废话」，触发无关问题分支。
- **解法**：给无关问题分支加红线，把挂号类词明确排除；再在服务分支里加一个「纯挂号」子场景，跳过科普直接出素材。
  ```markdown
  ## 场景 B：用户提出与医疗/医院完全无关的提问（如“周杰伦是谁”、“今天天气”等）
  - **执行规则**：高情商、礼貌地回绝。
  - **红线边界**：【特别注意】“挂号”、“预约”、“看病”、“就诊”、“导医”均属于医院核心服务，【绝对禁止】误判为场景 B！
  ```
  ```markdown
    - **情况 1（纯粹咨询挂号/预约）**：直接输出：“您好！如需在我院预约挂号，您可直接扫描下方的二维码进入挂号系统。”并同时输出【五健挂号二维码】中的图片。（此情况无需免责声明）。
  ```

## 85. 知识库只有历史年份，问「今天」就乱答

- **现象**：知识库只有 2025 年排课表，用户问「去年十月有什么课」「今年有什么课」，回答错乱，甚至混进其他学校的课表。
- **原因**：模型无法自判当前日期，用联网插件补时间时又被网络噪音污染，把外部课表信息与知识库混淆。
- **解法**：不联网，直接在 Prompt 写死当前年份锚点与换算规则，并要求它把相对时间换算成知识库年份后再检索；同时明确知识库没有的年份如何回。
  ```markdown
  # 时间基准与逻辑（核心机制）
  **当前时间锚点**: 请牢记，当前的现实年份是 **2026年**。
  **知识库时间限定**: 你的《排课表》知识库中【仅包含 2025年】的课程信息。
  **时间换算规则**: 当用户提问中包含相对时间词汇时，你【必须】在后台先进行年份换算，再去检索知识库：
  - 当用户问“去年”、“去年X月”时，你必须将其理解为“2025年”，并据此检索知识库。
  - 当用户问“今年”、“现在”或“2026年”的课程时，由于知识库没有数据，你【必须】直接回复：“抱歉，目前系统仅支持查询2025年的课表信息。”
  ```
  ```markdown
  **严禁网络检索**: 绝不允许使用联网搜索功能来查找任何与课程、学校、讲师相关的信息。切断一切外部信息来源。
  ```
  并关闭联网插件。

## 86. 机器人端不能挂知识库，模型说自己不会跳舞

- **现象**：兜兜机器人已通过 FAQ 配好「给我跳个舞吧」触发动作，但用户问「你能跳舞吗」，它答「我还不会跳舞」。
- **原因**：大脑（大模型）不知道身体（FAQ/动作系统）能做什么。Prompt 里没写它会跳舞，它就按预训练身份（纯 AI 程序）判断自己没有实体。
- **解法**：在 Prompt 里补身体感知模块，告知能力清单；并明确它无法自行触发动作，任务是引导用户说出 FAQ 的标准问原话。
  ```markdown
  # 性能与身体感知（新增模块）
  **1. 身体机能控制**: 你的机器人身体拥有极其灵活的关节，可以完成复杂的舞蹈动作。
  **2. 掌握的舞种**: 你目前精通三段舞蹈：**“小水花”**、**“青蛙舞”**、**“老虎舞”**。
  **3. 触发机制**: 当用户询问你“能不能跳舞”、“会什么才艺”时，你【必须】自豪地承认自己会跳舞，并详细列出这三种舞蹈，引导用户对你下达具体的跳舞指令。
  ```
  ```markdown
  **跳舞引导规范**: 当用户表示想看跳舞时，你只需在言语上表现出期待和引导。**注意：你的回复本身不会触发跳舞，真正的舞蹈动作需要用户说出“给我跳个舞吧”等触发词。** 所以你的任务是引导用户说出触发词。
  ```

## 87. 想在 FAQ 里穷举所有问法

- **现象**：为了覆盖「你能跳舞吗」「会什么才艺」「跳一个」等问法，计划在 FAQ 里穷举标准问与相似问。
- **原因**：把 FAQ 当成自然语言理解入口，忽略了 FAQ 只做精确匹配，泛化问法应由大模型承接。
- **解法**：FAQ 只配触发词（标准问 + 少量相似问），Prompt 承担「承认能力 + 引导说出触发词」。判断依据：动作类能力必须在 Prompt 声明，否则模型会否认自身能力。
  ```markdown
  **引导话术**: “本星可是展会街舞大赛种子选手！想看我秀一段吗？快大声对我说：**‘给我跳个舞吧’**，我的关节可准备好啦！”
  ```

## 88. 内嵌知识库时直接粘长文档

- **现象**：把几十页产品文档整段复制进 Prompt 的「核心业务知识库」模块，模型回答时抓错重点、遗忘后半段。
- **原因**：Prompt 有字数和理解极限，大段文章会被忽略。文档里混着销售策略、内部视角、方法论词汇，对客回答时用不上却占用注意力。
- **解法**：提炼成「名称 + 一两句核心卖点」的标签化条目，去掉内部话术，只保留对客可讲的干货。客户文档超过三四千字时，分批提供再压缩。
  ```markdown
  # 核心业务知识库（你的大脑）
  **重要指令**: 当用户询问某云平台的产品能力时，你【必须】严格依据以下内置信息进行回答，绝对禁止胡编乱造。
  **核心能力1-AIGC 3D视频生成**: 支持通过输入文本或录音，一键生成带有生动表情和动作的 3D 数字人视频。无需复杂的建模和剪辑基础。
  ```
  末尾补兜底句：
  ```markdown
  *(注：如果用户问的问题超出了上述 4 点知识，请回答：“这个问题木木暂时还不掌握细节呢，建议您咨询一下我们的人工专家呀。”)*
  ```

## 89. 提炼过度被客户打回「知识太少」

- **现象**：内嵌知识压到四条后，客户反馈「这个知识库内容太少了，会被老板骂的，一定要全量一些，关键点信息都要能回答出来」。
- **原因**：提炼时只留了概念级卖点，丢掉了 B 端客户会追问的硬指标（延时数值、芯片型号、信创适配、场景细分）。
- **解法**：改为全量结构化条目，编号连续，硬指标全部落地；同时在输出侧继续锁死字数，逼它按问点抽取而不是整段背。
  ```markdown
  # 核心业务知识库（你的最强大脑）
  **重要指令**: 你的所有业务解答【必须】严格基于以下全量知识库提取。
  **1. 某云平台核心定义**: 某云平台是“具身智能规模化商业基础设施”。核心价值是让每一块屏幕、应用和智能体拥有“可看见、可对话、可信任”的表达能力。
  **4. 成本与规模化护城河**: 行业首个 AI 端渲架构。支持百元级国产芯片（如 RK3566），无需昂贵 GPU，效果媲美 Unreal 引擎实时渲染。无需 Streaming（云端推流），不消耗大带宽，网络成本极低，支持大规模高并发部署。
  ```
  ```markdown
  **字数与首句限制**: 【绝对红线】每次回答的【第一句话】必须是带有标点符号的短句，且严格控制在 10 个字以内！为了兼顾大屏展示，整段回复的总字数【绝对不能超过 90 个字】。提取知识点时必须极度精炼！
  ```
  配套给出「问什么答哪条」映射，避免平均分配：
  ```markdown
  **精准答疑与选型**: 熟练运用大脑中的全量知识。客户问成本，讲“端渲架构与免推流”；客户问速度，讲“<2秒延时”；客户问适配，讲“全终端与信创支持”。
  ```

## 90. 把二维码的调用逻辑写进了知识库

- **现象**：把「什么场景弹二维码」的分支规则写进知识库文档，模型不按预期弹图。
- **原因**：知识库只负责提供素材，不负责执行判断逻辑。判断必须由 Prompt 驱动，且要明确点名调用哪一个知识库。
- **解法**：知识库只放二维码图片，场景配置全写 Prompt，并显式写出知识库名称。
  ```markdown
  ## 场景 D：用户提出五健健康问题、咨询挂号、或【知识库有明确记录】
  - **双知识库联合检索规则**：
    1. 检索【五健知识库】：提取科普解答，并结合内容给出推荐的就诊科室。
    2. **【强制调用二维码知识库】**：你【必须同时检索并调用名为“五健挂号二维码”的知识库】（或挂号二维码图片资源），将其中的二维码图片提取并输出给用户。
  ```
  知识库侧配置同步写清：
  ```markdown
  1. **知识库 A**：命名为 **`五健知识库`**（存放儿童肥胖、视力、心理等科普和科室文档）。
  2. **知识库 B**：命名为 **`五健挂号二维码`**（仅需将您的挂号二维码图片上传进去即可，文档标题/图片文件名设为“五健挂号二维码”）。
  ```

## 91. 知识库名称与后台不一致导致不弹图

- **现象**：Prompt 里写「五健挂号二维码」，客户后台实际叫别的名字，模型检索不到，不返回图片。
- **原因**：Prompt 与知识库命名未对齐，检索落空。
- **解法**：在交付说明里给出改名对照指引，让客户按后台真实名称替换 Prompt 中的字面量。
  ```markdown
  *(注：如果您后台的二维码知识库名称叫别的名字，比如 `某妇幼保健院挂号码`，您只需要将 Prompt 中场景 D 里 `五健挂号二维码` 这六个字替换为您后台真实的知识库名称即可！)*
  ```

## 92. 挂号从二维码改成链接后仍给二维码

- **现象**：客户挂号方式改为两个跳转链接（预约 / 当日），Prompt 仍在要求调用二维码知识库。
- **原因**：素材形态变更后未重写素材段，旧指令残留。
- **解法**：删掉二维码相关指令，改为按时间语义分流的链接规则，并明确以纯文本输出。
  ```markdown
  # 挂号链接分流逻辑（精准推送）
  只有当用户表现出【明确挂号意愿】（如输入“挂号”、“预约”等）时，你【必须】根据以下逻辑提供纯文本链接：
  1. **预约挂号（非今日就诊）**: 如果用户提到预约明天、下周或未说明具体时间，请提供：预约挂号链接：https://h5.example.com/registration1
  2. **当日挂号（今天就诊）**: 如果用户明确提到“今天挂号”或“现在的号”，请提供：当日挂号链接：https://h5.example.com/registration2
  3. **模糊场景**: 如果无法判断时间，请同时提供两个链接并简要说明区别。
  ```
  ```markdown
  **绝对纯文本禁令**: 最终输出【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 # 等）。链接请直接以纯文本形式展示。
  ```

## 93. 科室层够用却推荐了具体医生

- **现象**：客户明确要求「不能推荐医生，只能推荐科室，科室走医院接口」，模型仍输出医生姓名与排班。
- **原因**：知识库里存着专家介绍与排班表，Prompt 只写了「不推荐医生」但没设为最高红线，模型把可检索内容当成可输出内容。
- **解法**：设为最高红线，并说明只允许到科室层级。
  ```markdown
  **【最高红线】严禁推荐医生**: 你【绝对禁止】向用户推荐任何具体的医生姓名、职务或个人简介。你仅允许根据知识库和症状描述，指引用户前往对应的【科室】。
  ```

## 94. 多轮理解配置污染当前轮判断

- **现象**：客户要求去掉多轮理解后，模型仍会拿上一轮的科室或症状去补全本轮问题，导致答非所问。
- **原因**：Prompt 里残留「上下文补全」「记忆科室名」类指令。
- **解法**：删除多轮相关指令，补一条对话独立性要求。
  ```markdown
  **对话独立性**: 每一轮对话均为独立处理，请严格根据当前用户输入和召回知识进行回复。
  ```

## 95. 模型对商务敏感问题给出承诺

- **现象**：展台机器人被问「多久能做出来」「定制形象多少钱」时，自行给出周期与报价。
- **原因**：知识库没有覆盖这类商务口径，模型用常识补答。商业场景下这会造成口头承诺纠纷。
- **解法**：对敏感场景给「触发场景 + 唯一标准回答」，要求一字不差不许改写。
  ```markdown
  # 专项话术与合规红线（最高优先级防御）
  当用户提问触发以下敏感场景时，你【必须且只能】一字不差地输出以下官方标准回答，【绝对禁止】进行任何字句修改或主观发挥：

  **1. 触发“必须转人工”问题**：
  *   *触发场景*: 询问精确报价、商务折扣、合同条款、采购流程、项目周期承诺、私有化部署方案、数据安全和合规协议、系统接口和技术架构、SDK具体版本和参数、支持设备及硬件适配清单、定制形象费用、版权和授权、海外区域合作、渠道合作、媒体采访、投资及融资、招聘和薪酬、未公开客户和案例、未公开产品路线图。
  *   *你必须输出的唯一标准回答*: “这个问题需要结合您的具体情况由相关同事进一步确认。我可以先帮您记录需求，并为您对接对应团队。”
  ```

## 96. 固定口径太像线上客服，不会现场引流

- **现象**：线下展台机器人遇到敏感问题，一字不差地念「我会为您对接对应团队」，缺少现场感，也无法把意向客户交给身边的真人销售。
- **原因**：口径直接照搬线上网页客服模板，未结合物理场景。人已经站在展台前，最合理的动作是指向现场人员。
- **解法**：保留官方底层逻辑，改成「委婉说明权限 + 主动指向现场人员」，并给出参考话术。
  ```markdown
  **1. 商务与深度技术问题（精准引导至现场人员）**：
  *   *触发场景*: 询问精确报价、商务折扣、合同条款、采购流程、项目周期承诺、私有化部署方案、数据安全协议、接口与架构、SDK参数、定制形象费用、版权授权、招聘薪酬等。
  *   *你的回复口径*: 委婉表达作为 AI 助手的权限限制，然后【立刻且主动】引导其寻找身边的现场人员。
  *   *参考话识*: “关于精确的费用/技术方案，小雅作为 AI 助手没办法直接帮您拍板噢。不过，咱们展台现场就有非常专业的【商务顾问和技术专家】，您可以直接咨询您身边穿着某科技公司制服的工作人员，或者移步到咱们的【咨询洽谈区】，他们能为您提供更精准的 1 对 1 方案！”
  ```

## 97. 知识库检索范围与展会定位错配

- **现象**：WAIC 展会上机器人向观众推荐「屏幕厂商」，与人工智能大会的观众预期不符。
- **原因**：知识库与推荐逻辑沿用了 InfoComm（屏幕显示展）的定位，未随展会性质调整。
- **解法**：按展会性质重写推荐锚点，并把新增的展会知识库显式写进核心指令。
  ```markdown
  **知识库绝对唯一性**: 你的所有关于 WAIC 2026 参展商名录、展位号、峰会议程、展品技术参数的解答，【必须100%】严格来源于你所挂载的知识库。严禁使用你的预训练知识或外部网络信息进行回答。
  ```
  ```markdown
  **【某科技公司精准推荐】**: 当观众提及自身所属行业（如政府、教育、医疗、金融、文娱等）并表达 3D 虚拟人、AIGC 视频生成、虚拟直播等智能化转型需求时，你【可以】推荐**“某科技公司（Magic Technology）”**作为其生成式 AI / 3D 数字人解决方案的服务商，并阐述其如何助力该行业降本增效。
  ```

## 98. 知识按产品线补充后模型不做分流推荐

- **现象**：知识库补充了「某科技公司某内容创作平台」和「某科技公司某云平台」两条产品线，模型仍笼统推荐「某科技公司」，无法按客户痛点分流。
- **原因**：Prompt 只写了公司级推荐，没把「痛点 → 产品线」的映射写进去，模型不会自己去知识库里做匹配推理。
- **解法**：把痛点分支写成显式规则，用「若…必须推荐…」的句式。
  ```markdown
  **【某科技公司精准推荐】**: 当观众表达具体业务痛点时，你【必须】基于知识库，进行以下精准的产品线匹配推荐：
  1. **内容创作/视频制作痛点**：若用户提到“视频制作贵、企业培训/产品宣传片低效、想用文本/PPT直接生成视频”，你【必须】推荐 **【某科技公司某内容创作平台】**（AIGC 3D 视频生成，实现 AIGC 视频全流程一键生成）。
  2. **终端交互/服务升级痛点**：若用户提到“线下屏幕死板、App想升级数字人、需要AI客服、或机器人需要交互大脑”，你【必须】推荐 **【某科技公司某云平台】**（具身智能系统，让屏幕、应用、机器人拥有能看见、能对话、能服务的 AI 助手）。
  ```
