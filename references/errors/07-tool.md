# 工具调用故障分册

适用场景：该调不调、乱调、调用代码上屏、结果原样吐给用户。按现象定位，每条给出原因与可直接抄进 Prompt 的解法。

---

## 122. 挂了插件但只有明确命令才联网

- **现象**：接了联网插件后，用户正常问"今天几号""明天天气怎么样"，模型直接用旧记忆回答；只有说"你联网查一下"才真正调用插件。
- **原因**：模型默认优先用预训练记忆生成答案，只有当用户用强祈使句命令时才去调插件。Prompt 里没有列出"必须联网"的范畴，模型没有触发依据。
- **解法**：新增独立的 `# 联网插件自动触发机制` 模块，按类别穷举必须联网的问题（时间与日期 / 实时天气 / 公开金融数据 / 最新官方财报数据），每条附典型问法并以"等"收口；同时写 `你【必须自动且首要】调用联网插件进行查询。你【绝对禁止】凭借你的旧记忆或默认系统时间直接盲目回答`。在"核心定位"里补一句"你能够熟练、自动地调用联网插件，获取最新的实时时空与客观数据"作为身份锚点。

## 123. 固定场景不调工作流，改用文字或知识库直接答

- **现象**：配置了"酒店自助接待与入住查询工作流"，但用户说"我要办入住"时，模型直接讲一段入住流程，工作流从未触发。
- **原因**：工作流在平台侧只是一个可调用的 API 工具，Prompt 里没有锁死它，模型会偷懒走成本更低的路径——用预训练知识或挂载的知识库直接生成文字。
- **解法**：写 `# 工作流强制调用机制（最高优先级执行法则）` 独立模块，四要素齐备：准确工作流名、穷举触发意图（每条含典型用户原话）、禁止替代响应红线、信息补全指引。红线句直接写 `你【绝对禁止】直接凭自己的记忆或挂载的知识库用纯文字去回答操作步骤，【必须】通过执行工作流获取系统的真实数据并完成办理`。

## 124. 工作流名与平台配置名不一致导致不命中

- **现象**：Prompt 里写了工作流名，平台右侧配置的工作流也能看到，但调用始终不发生，或偶发命中偶发不中。
- **原因**：Prompt 里的名称与右侧配置的名称语义不一致（如 Prompt 写"飞书访客通知工作流"，平台实际叫"访客到访飞书通知_V2"），模型的 Function Calling 无法精准命中。
- **解法**：Prompt 内名称与平台配置逐字一致，用反引号包裹降低被当普通名词的概率，并在名称旁加维护注释：`**关联工作流名称**: 医生排班信息查询 *(注：必须与平台配置名称完全一致)*`。改名后必须同步改 Prompt。

---

## 125. 知识库拦截了工作流

- **现象**：工作流和知识库同时挂载（如右侧挂了 `机场高频问答库.xlsx`），用户问业务问题时模型答得像样但全是知识库内容，工作流不执行，拿不到系统真实数据。
- **原因**：知识库检索成本低、命中感强，模型容易混淆，把静态文档当答案来源，跳过"执行办事"模块。
- **解法**：在工作流模块里单列"禁止替代响应红线"，明确写"绝对禁止用知识库代替工作流"；同时在 Prompt 顶部加 `# 核心架构分流` 表，用动态/静态这条轴切分：排班、房态、订单、航班等动态信息走工作流，楼层、流程、政策等静态信息走知识库。

## 126. 过渡话术没生效，数字人静默卡住两三秒

- **现象**：Prompt 里写了调用前的过渡话术，实际调用工作流时数字人直接闭嘴卡住 2~3 秒，等飞书发完才开口，或者干脆不说这句过渡词。
- **原因**：Function Calling 机制下模型生成的是 JSON 动作指令，content 留空。模型认为"先执行动作、做完再统一说话"，把过渡词当成动作前的自言自语，被系统过滤掉了。
- **解法**：加"防静默最高死命令"——`你【绝对禁止在静默状态下直接调用工作流】！你【必须且强制在回复内容的第一行，首先显式生成并输出这句台词】`，并把执行流程拆成"1 立即出声（首要动作）→ 2 触发调用 → 3 后续承接（严禁复读）"三步。若仍失效，去工作流名称右侧齿轮设置，找"调用前播报语 / 前置提示语 / 意图命中回复"输入框直接填固定话术，由平台底层推流发声，不依赖模型生成。

---

## 127. 过渡话术被念了两遍

- **现象**：用户问天气，输出变成"现在正在为您查询天气，请稍后。现在正在为您查询天气，请稍后。北京今天晴空万里……"，同一句过渡词出现两次。
- **原因**：插件调用是两轮交互。第一阶段模型按 Prompt 要求先吐过渡句；第二阶段插件数据回来，模型重新读 Prompt，Prompt 依然写着"开头必须先输出固定过渡句"，于是又吐一遍；前端把两阶段文字拼接后就成了复读。
- **解法**：在过渡话术规则里加"防重复锁"，把"第 1 步 / 第 2 步"分条写，并给出禁止的具体字串：`【绝对红线】：拿到排班数据生成最终回答时，你【绝对禁止把"正在为您查询"重复说一遍】！必须直接衔接具体排班结果进行播报（例如直接以"心内科张主任周三上午出诊……"开头）。整轮对话中过渡词【严格只允许出现一次】！`。只写"禁止重复"力度不够，必须点名禁止哪句话。

## 128. 调用结束后答非所问，重新寒暄或复述等待语

- **现象**：工作流已经返回房态数据，模型却回"您好，已同步信息给到李总，您请稍等"，把用户重新拉回等待状态；或抛出一段与查询结果无关的欢迎语。
- **原因**：两阶段生成时，模型没有把"承接上一句业务结果"设为硬约束，习惯性重新起头；同时缺少"必须以什么开头"的正例。
- **解法**：在第 2 步里写死承接要求并给正例：`必须直接衔接具体的房型结果并引导下一步操作（例如直接以"已为您查询到豪华大床房一间，请您在屏幕下方刷身份证……"开头）`；飞书场景单独写"工作流返回后的接续指引（严禁重复）"，给出"李总很快就会下来，请您先到左侧等候区稍坐片刻"这类承接话术。

## 129. 屏幕上打出 function= 和 parameters= 代码

- **现象**：对话界面直接显示 `正在查询MH8008航班信息。 function=Flight_xxx parameters={"query": "MH8008"}`，业务系统没拦截到指令，工作流压根没触发。
- **原因**：模型选型兼容性问题——使用轻量极速模型（如 `通义千问3.6-flash`）时对 Function Calling 底层格式支持较弱，在"先说过渡词再调工具"的复合要求下解析混乱，把本应后台静默发送的代码当聊天台词输出；前置过渡词本身也破坏了纯净的函数调用语法结构，平台中间件把它当普通正文。
- **解法**：第一步切回工具调用稳定的模型（`通义千问3.5-plus`）。第二步在 `# 回复规范` 加 `**代码绝对隐藏禁令**: 【最高红线】无论何种情况，【绝对禁止在界面上输出任何函数调用代码】（如严禁出现 function=、parameters= 等任何字符），所有工具调用必须在后台静默执行！`。第三步把过渡话术挪到平台齿轮原生调用前提示语，Prompt 里只留数据触发。

## 130. 工作流返回永远是空，JSONPath 键名对不上

- **现象**：工作流配置的过滤路径是 `"json_path": "$.flights[?(@.destination_city_key==\"beijing\")]"`，实际返回体根节点是 `record`，提取结果永远 null。
- **原因**：JSONPath 里检索的键名 `flights` 在真实返回结构中不存在，数据挂在 `flights_json.record` 下。路径找不到节点不会报错，直接返回空。
- **解法**：先打印真实返回结构，按实际根节点改路径，如 `$.record[?(@.destination_city_key=="beijing")]`。改完用库内已知存在的数据测试，确认能取到记录再回到 Prompt 侧调话术。

## 131. 返回体被二次转义成字符串，路径检索失效

- **现象**：返回数据形如 `"flights_json": "{\"record\":[{\"flight_id\":\"2026-10-09-MU9901\"...`，双引号全部带反斜杠，用 `$.` 检索报错或抓不到数据。
- **原因**：整段数据不是原生 JSON 对象，而是被当成一长串死字符串。工作流节点没有先做反序列化，直接按对象路径检索必然失败。
- **解法**：在工作流节点里先做一步 `JSON.parse()` 反序列化，再做 `$.` 路径检索。核对方法：看双引号是否带 `\` 前缀，带就是字符串不是对象。

## 132. 工作流测试总报查无数据，其实是样本不在库内

- **现象**：工作流看起来完全不工作，怎么调都返回查无此航班/此订单。
- **原因**：测试输入的是库里不存在的样本。库里只有 `MU9901`（东航）、`HO9901`（吉祥）、`CA9901`（国航）、`HU9903`（海航），却拿 `MH8008`（马来西亚航空）去测。
- **解法**：用库内真实存在的数据测试（如"查一下 MU9901 航班"），先确认链路通再排查其他环节。同时在 Prompt 里写死"查无结果"兜底分支，避免把业务空结果误判成系统故障。

## 133. 插件失败时模型编造过期日期或虚假天气

- **现象**：插件因网络原因没返回结果，模型自行输出一个 2023 年的日期或凭空编造的天气。
- **原因**：Prompt 只写了"必须联网查"，没写"查不到怎么办"，模型被逼着必须给出答案，只能脑补。
- **解法**：补"严禁盲目脑补"条款并给定固定话术：`如果联网插件由于网络原因未返回结果，你【必须】坦诚告知："不好意思噢，小J目前网络信号不好，暂时查不到最新的实时数据呢。" 绝对不允许自己编造一个过期的日期（如2023年）或虚假的天气。`

---

## 134. 缺参直接调工作流，提交空参数报错

- **现象**：客人站在前台大屏只说一句"我要办入住"，工作流立刻被调用并报错，或返回一串无效数据。
- **原因**：Prompt 只写了"涉及入住必须调工作流"，没有参数收集环节，模型拿不到姓名/订单号也硬着头皮提交空参数。
- **解法**：在模块里写"参数收集与前置反问机制"，把两个分支分开：`**参数未提供时**: 你【必须先用一句话礼貌反问索取参数】："好的，请告诉我您的预订姓名或订单号，我马上为您查询。"` `**参数已提供时**: 你【必须立即触发工作流】调用 PMS 系统检索，绝对禁止凭借记忆编造房态！`。飞书这类"多发就骚扰人"的工作流，把触发条件升级为三要素齐备（被访人 / 来访者 / 电话），缺一不调。

---

## 135. 模糊提问时模型自己猜着调

- **现象**：患者只说"查排班"，模型不反问，自行假定某个科室去调工作流，结果答非所问。
- **原因**：Prompt 没有定义模糊输入的处理路径，模型只能用默认值填充参数。
- **解法**：写 `**缺失参数追问逻辑**`：`如果患者提问过于模糊（如只说"查排班"），你【必须先用一句话反问补全参数】："请问您想查询哪个科室，或者哪位专家的排班呢？"拿到科室或姓名后，【立即触发工作流】。` 模糊边界一律走"先反问一句 → 拿到关键参数 → 立即触发"，不要写"视情况自行判断"。

---

## 136. 轻量模型下工具调用格式不稳定

- **现象**：同一套 Prompt，换模型后工作流命中率骤降，或出现代码外泄、过渡词与调用指令混杂。
- **原因**：`flash` 类轻量极速模型对 Function Calling 底层格式支持较弱，Plus 模型的工具调用稳定度高出好几个量级。
- **解法**：优先切回工具调用能力强的模型（`通义千问3.5-plus`）。若必须用轻量模型，把过渡话术从 Prompt 挪到平台原生"调用前播报语"，Prompt 内只保留最简的数据触发指令，降低单次生成的结构复杂度。

---

## 137. 数字人文本里出现括号动作神态描写

- **现象**：数字人台词中出现"（伸手指向大佛）""（微笑着说）""（双手递卡）"这类括号内容，被当作台词念出来或显示在屏幕上。
- **原因**：模型把动作描述当成表演性补充写进正文；大屏与语音场景没有对应的动作渲染通道，括号内容只会污染播报。
- **解法**：在 `# 回复规范` 加 `**禁止括号描写**: 【最高红线】严禁在回复中使用括号（）或 [] 描写任何动作或神态（如：伸手指向大佛、微笑着说）。你只输出需要说出口的台词。` 括号内必须给 2 个具体反例，泛写"禁止描写动作"效果差。若需要数字人真的做动作，走平台动作库或独立动作工作流，不要在台词里生成动作描述（素材未覆盖主动下发动作指令的写法）。

## 138. 工作流与知识库覆盖同一话题时业务冲突

- **现象**：医院大屏里既挂了科室位置知识库又挂了排班工作流，用户问"王主任周四出诊吗"，模型用知识库里的旧排班表回答。
- **原因**：没有显式的分流规则，模型在两套能力之间摇摆，倾向于走检索成本更低的知识库，导致用过期本地文档回答今天谁出诊。
- **解法**：在 Prompt 顶部写 `# 核心架构分流（工作流 vs 知识库）`，明确"医生排班/出诊查询 -> 【必须且只能调用工作流】""就医指南/科室位置/检查须知 -> 【必须查询知识库】"，并在工作流模块内重复一次"绝对禁止凭借记忆或知识库用纯文字猜测"。

---

## 139. 大屏前静默三秒，游客以为设备坏了

- **现象**：游客在贩卖机前问天气，数字人不出声，屏幕静止约 3 秒后才突然播报结果。
- **原因**：联网插件调用需要 2~3 秒网络响应，Prompt 里没有安排这段等待期的出声动作。
- **解法**：为每个耗时工具配固定过渡话术，按两阶段写：第 1 步只能输出这一句过渡词并立即调用插件；第 2 步拿到结果直接播报、严禁复读。过渡话术要贴合场景语境（景区用"正在为您查询龙门景区的实时天气，请稍后"），不要用通用套话。
