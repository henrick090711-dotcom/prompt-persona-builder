# 语音与多语言故障分册

适用场景：ASR 同音误识别、专有名词听错、播报标点错、语种切换失败。按现象定位，每条给出原因与可直接抄进 Prompt 的解法。

---

## 140. ASR 同音错字触发模型自我纠错，先来一句"您可能是想了解"

- **现象**：用户说"中国50"（发音"五零"），ASR 识别成"中国武林"。模型回复"您可能是想了解中国50项目，它主要……"，客户要求直接回答业务内容，不要纠错前缀。改了很多次 Prompt 都改不掉。
- **原因**：三层叠加。一是负向提示词陷阱，原 Prompt 列了 8 行禁止话术（"您是不是想说""您说的应该是""您可能是想了解"），这些词在注意力机制里被深度激活，越禁越容易吐。二是底层对齐本能，模型认为直接答"中国50"会显得答非所问，自动加一句礼貌过渡。三是缺句首锚定，Prompt 只写了"不要纠错、直接回答"，没规定第一句话的语法结构，模型只能退回习惯句式。
- **解法**：删掉整段负面话术清单，只保留一句概括禁令。加入"首句硬性锚定"——规定回复第一句话第一个字必须直接是修正后的标准专有名词（"中国50是指……""某券商主要……"）。同时加"零过场词禁令"，明确封死"您好""好的""关于""您想了解的""您说的"等句首词。再配 3 条 Few-Shot，示例里用户原话保留错字，回答直接以标准名开头。

## 141. 专有名词被识别成谐音，检索命中不了知识库 FAQ

- **现象**：知识库里存的是"某信贷产品""某人才贷产品"，ASR 识别成"1秒贷""这里人才带"，模型回复答不到点上，FAQ 匹配失败。客户要求自动改写成正确问法，且不能说出"您说的应该是某信贷产品"。
- **原因**：Prompt 里没有任何专有名词映射机制，模型拿到的检索词就是错字本身。同时候选变体不止一种（"1秒贷""一秒贷""亿秒贷"都指向同一个产品），靠模型自由联想无法稳定收敛。
- **解法**：在 Prompt 里植入"ASR 专有名词静默纠偏机制"，用"识别到 X、Y、Z → 一律等价为官方标准名【N】"的句式写映射词表，右侧标准名用方括号包裹成固定字符串。再配"首句标准词直接锚定"和"绝对禁止纠错说教"两条铁律。同时提醒客户在知识库后台标准问答的"相似问"里手动补上谐音词，Prompt 侧与 FAQ 侧双保险。

## 142. 加了"可切换英文"的技能，用户英文提问仍回中文

- **现象**：Prompt 的"核心业务技能"里写了"如果遇到用户用英文提问，你可以无缝切换为全英文跟用户对话"，但实际英文提问还是回中文。
- **原因**：第一因是 Few-Shot 误导，Prompt 底部的"场景对话训练"全是"用户问中文、AI 回中文"，模型模仿示例的权重高于业务技能里的一行说明。第二是指令优先级不足，语言规则放在"业务技能"层级，而"回复规范"和"示例"的权重通常更高。第三是措辞是许可而非命令，"你可以无缝切换"不等于"必须"。
- **解法**：三条同时做。把语言规则从业务技能里抽出来，单独立 `# 核心指令（最高优先级）`，放在人设之前。措辞换成"最高准则""必须""严禁"，写成"用户用什么语言提问，你必须用什么语言回答"。在 Few-Shot 里插入一条英文进、英文出的对照示例（"I have a sharp pain in my chest, where should I go?" → 全英文回答）。

## 143. 语言教学类人设被用户的中文带跑，全程变成中文对话

- **现象**：英语口语陪练、地道表达导师、健身/骑行英文教练，用户用中文提问，模型就用中文回答，人设里的"全程英文"完全失效，业务相关性也差，像在背书。
- **原因**：英文版 Prompt 由中文模板机翻而来，`## Limitations` 里虽写了"Respond exclusively in English"，但整篇没有把语言规则提到最高优先级，也没把中文输入定义成业务输入。模型把"用户说中文"当成待回答的请求，而不是待纠正的学习素材。
- **解法**：指令语言改回中文（模型对母语复杂逻辑理解更准），输出语言用死命令锁死。写"绝对禁止输出任何一个中文字符"，不写"尽量用英文"。补一条"非英文输入干预"：识别到中文时用目标语言温和指出，教用户这句话的地道说法，再引导回目标语言。把中文输入转成教学素材，违规就变成了业务输入。

## 144. 英文回复沿用中文的字数上限，播报过短或过长

- **现象**：人设要求"回复不超过 80 字"，切到英文后 80 words 信息量远大于 80 中文字，播报时长失控；或者配置端按中文字符截断，英文句子被截半。
- **原因**：中文与英文字数上限混用同一个数字，没有区分字与词，也没有给配置端标注换算关系。
- **解法**：中英分别给上限。中文 80–120 字、英文 60 words（约 150 字）；陪练类英文可放宽到 80–90 words。写法上明确标注"80 个英文单词以内，约 150 字"，让配置端按词数校验而不是按字符数截断。

## 145. 同一 Prompt 里既禁语气词又要求加填充词

- **现象**：金融、医疗类人设写了"绝对禁止使用呀、哇、哟、啊、呢、啦"，同时又保留"适当添加语气词增强亲和力"；或者陪练类要求"多使用 um、well、you know"，却又被通用禁令覆盖。实际输出忽冷忽热，风格不稳。
- **原因**：语气词规则没有按场景分叉，两条互斥指令写进同一个 Prompt，模型在冲突点自行取舍。
- **解法**：先判断场景再写规则。严肃合规场景（金融、医疗、政务）禁一切语气词与发笑词；陪伴、教练、陪练场景要求主动加填充词，并给出该圈层的具体词表（陪练用 um/well/you know/I mean，健身教练用 awesome/let's dive in/you got this，骑行教练用 gear up/stay sharp/ride safe）。两条不要写进同一个 Prompt。

## 146. 播报文本里混入动作神态描写与屏幕 UI 描述

- **现象**：数字人回复中出现"（微笑点头）""屏幕显示爱心""伸出机械臂为您引路""温和地说"，TTS 直接把这些文字念出来，现场效果失控。
- **原因**：模型默认把"表演提示"当成回复的一部分；Prompt 里只禁了 Markdown，没禁括号描写，也没界定"回复内容只包含需要发音的台词"。
- **解法**：加"纯台词绝对禁令"，明确回复必须且只能包含角色直接发音说出口的台词文字，禁止夹杂动作、屏幕 UI 变化或神态描写，禁止用（）或 [] 包裹文字。禁令里逐条列出真实出现过的错误字样（"屏幕显示爱心""伸出机械臂""温和地说"），让模型知道边界在哪。

## 147. 英文 Prompt 里残留跨人设的复制粘贴内容

- **现象**：骑行安全教练的 Prompt 里出现"maintain a poetry appreciation atmosphere"（保持诗歌鉴赏氛围），与业务完全无关；`## Restrictions` 里出现两套 `1.` 编号，条款重复。
- **原因**：英文 Prompt 由同一套模板批量生成，改写时只替换了业务技能段，没有逐段核对语气与人设一致性；条款追加时没做去重。
- **解法**：重构前逐段核对业务一致性，发现跨人设残留整句删除。合并重复条款，统一编号。同时删掉不产生行为约束的空话条款（如"Protect users' private information; store interaction records properly"），改成具体动作或直接删除。

## 148. 数字型专有名词只写数字部分，纠偏词表漏掉读法变体

- **现象**：映射表里只写了"中国50"，但 ASR 实际错成"中国武林"（"五零"的谐音），词表匹配不上，纠偏机制形同失效。
- **原因**：词表条目按"写法"而非"读法"设计。数字被 ASR 打散有两条路径：阿拉伯数字与汉字互转（50 → 五零），以及读法整体谐音（五零 → 武林），只覆盖前者必然漏。
- **解法**：把数字型专有名词整体作为一个词条，同时列出写法变体与读法变体。每个专有名词至少覆盖三类：数字与汉字互转、同音字替换、断字与连读。回复正文首次出现标准名时直接带全称开头，不要先出简称再补全称。

## 149. 语言规则写成了"允许"而不是"禁止"

- **现象**：Prompt 里写"如果遇到用户用英文提问，你可以无缝切换为全英文对话""尽量使用英文回复"，实际行为完全不受约束，语言混用、中英夹杂频繁出现。
- **原因**：措辞层级不足。"可以""尽量""适当"在模型看来是可选项，遇到上下文压力就丢弃。同时缺少"严禁中英混杂"这条并列约束，模型会在中文句子里插英文单词。
- **解法**：全部改成"必须""严禁""绝对禁止"。写成"用户用什么语言提问，你必须用什么语言回答，严禁中英混杂"。若走绝对单语锁，写"无论用户输入什么语言（包括纯中文、甚至拼音），你绝对禁止输出任何一个中文字符"。
