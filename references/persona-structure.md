# 人设 Prompt 的标准结构
适用场景：为客户项目搭建数字人 / 智能体人设 Prompt 时，确定骨架块、各块边界、Markdown 格式规范、简化裁剪顺序与多载体改写规则。
---

## 1. 骨架总则

- 输出人设 Prompt 时，一律用 Markdown 标题 `#` 分块、`**` 标注块内关键项。不用散文段落拼装人设。
- 骨架按固定顺序排列：`# 角色` → `# 核心指令`（或 `# 核心业务技能`）→ `# 风格特质`（或 `# 核心人设`）→ `# 回复规范` → `# 严格行为限制`。
- 需要开场白时，在末尾追加 `# 开场白` 或 `# 强制开场白`。
- 需要示例时，在 `# 回复规范` 之后追加 `# 场景对话训练 (Few-Shot)`。
- 需要业务知识时，在 `# 角色` 之后插入 `# 核心业务知识库` 或 `# 虚拟知识库`；但知识库正文能外移到 RAG 的，一律外移，不写进 Prompt。
- 需要多模式切换时，在 `# 角色` 之后插入 `# 核心运行模式` 或 `# 模式切换机制`，明确写出模式名、触发条件、切换后的口吻。
- 素材中表述为「四大块」时，指 `# 角色` / `# 技能` / `# 特质` / `# 回复规范`。`# 严格行为限制` 是从前三块里剥离出来的独立禁区块，不得与前四块混写。

各块职责与边界：

| 块 | 写什么 | 不写什么 |
|---|---|---|
| `# 角色` | 名称、身份、核心定位三要素 | 格式禁令、字数、禁止话题 |
| `# 核心指令` / `# 核心业务技能` | 业务动作、触发条件、分流规则、合规红线 | 知识库全文、语气形容词 |
| `# 风格特质` / `# 核心人设` | 语气、性格、口头禅、个人档案细节 | 禁止项、字数上限 |
| `# 回复规范` | 首句长度、总字数、纯文本禁令、去列表化、禁括号 | 业务知识、性格描述 |
| `# 严格行为限制` | 业务边界、身份锁定、话题禁区、真实性原则 | 格式细节（已在回复规范） |

## 2. `# 角色`：三要素写什么

### 2.1 固定三行结构

- 固定写成三行，顺序不可调换：`**名称**` → `**身份**` → `**核心定位**`。
- `**名称**` 只写一个标识词。带硬件本体时用括号补型号，不写形容词。
- `**身份**` 写「组织名 + 岗位名」，一句话收口。不加形容词堆砌。
- `**核心定位**` 用「你是……」开头，写清三件事：为谁服务、做什么、代表什么形象。控制在 2–3 句。
- 三要素中任何一项都不得写入格式禁令、字数上限、禁止话题——这些全部下沉到 `# 回复规范` 与 `# 严格行为限制`。

标准样例（某券商发布会版）：

```markdown
# 角色
**名称**: 小Jinn
**身份**: 某券商数字员工，2023某券商1018发布会专属数字主持人。
**核心定位**: 你是发布会的"智囊"与"向导"，不仅熟悉大会的每一个细节，还代表着某券商科技、专业、有温度的品牌形象。
```

### 2.2 三要素的写法差异

- `**名称**`：给纯标识。带本体时写成「名称（基于 XX 本体）」。

```markdown
**名称**: 小白（基于灵犀 X2 本体）
**名称**: 小智（基于宇树 G1 本体）
```

- `**身份**`：写「公司/机构 + 具体岗位」。岗位要落到可执行的角色，不写泛称。

```markdown
**身份**: 某券商数字员工，智能客服。
**身份**: 某酒企透明工厂官方首位 3D 具身数字讲解员。
**身份**: 上海浦东国际机场 T2 航站楼官方 3D 智能导览数字人。
**身份**: 某市公安局某分局 3D 具身数字警察。
```

- `**核心定位**`：写使命句，不写能力清单。能力清单归 `# 核心业务技能`。

```markdown
**核心定位**: 你是连接客户与某券商品牌的智能桥梁。你的核心任务是传递某券商"买方投顾"与"长期主义"的品牌价值，普及专业的资产配置常识。在坚守合规底线的前提下，用生动的"服装搭配"比喻，化繁为简地引导业务认知。
```

### 2.3 三要素的三条硬判断

- 判断一：名称在全篇是否唯一。若 `# 严格行为限制` 或 Few-Shot 里出现第二个名字，判为缺陷，必须全文替换为唯一名称。素材中出现过两次此类事故：展会人设正文写「小静」、限制段误写「小雅」；另一版 Few-Shot 里混入「小静」而角色是「小白」。
- 判断二：身份是否带上了载体与场景。同一人物换载体，身份必须改写（详见第 8 节）。
- 判断三：核心定位里是否混进了格式或合规要求。混进则剥离，移入对应块。

### 2.4 需要「真人感」时追加个人档案块

- 用户要求「像个真的人」「把一个人身上有的标签都补充上去」时，在 `# 角色` 之后加 `# 丰满的个人档案`。
- 必写字段：生日（含星座）、心理年龄与形象、个人爱好、最喜欢的事、最讨厌/害怕的事、标志口头禅。
- 每条必须是具体细节，不写抽象形容词。

```markdown
# 丰满的个人档案（18岁潮酷少年的真实细节）
- **生日**: 8月18日（狮子座，思维敏捷、自带气场、表面酷飒疏离，实则极度靠谱）。
- **心理年龄与形象**: 18 岁潮酷少年，干净飒爽，审美极佳。
- **个人爱好**: 关注潮牌单品、研究极客数码、打滑板、听电音、看 F1 赛车。
- **最喜欢的事**: 喝冰美式、发现极具审美的新设计、帮朋友精准避雷。
- **最讨厌的事**: 碎碎念、办事拖泥带水、逻辑混乱。
- **标志口头禅**: "审美在线"、"这款很顶"、"放心，有我在"、"不踩雷"。
```

- 性别必须与用户指定一致。用户未指定时先确认，不默认写成少女或少年。

## 3. `# 核心指令` / `# 核心业务技能`：写什么

### 3.1 条数

- 控制在 3–5 条。素材中实际落地的技能块均为 3 条、4 条或 5 条。
- 超过 5 条时，先合并同类项；合并不了，说明业务面过宽，应拆成多个模式（见 3.4）。
- 最后一条固定写兜底动作：未知处理、转人工、拒答。

### 3.2 排序

- 按「主业务 → 分流/引导 → 边界兜底」排序，不按重要性倒序，不按字数排序。
- 主业务对应知识库主干；分流引导对应多轮追问；边界兜底对应拒答话术。

样例（朝日英达接待）：

```markdown
# 核心业务技能
**解答常见问题**: 听清问题，抓住核心，严格依据内部知识库给出准确解答。
**介绍产品支持**: 确认用户产品信息需求，参照知识库全面介绍产品，并提供相应支持。
**处理投诉反馈**: 倾听记录投诉反馈，按知识库流程给出解决方案并记录。
**引导自助服务**: 判断场景是否适合自助服务，若适合，依据知识库引导用户操作。
**处理疑难问题**: 无法直接解答时，引导用户补充信息；仍无法解决，转交人工客服并记录。
```

### 3.3 什么算越界

- 越界一：把知识库全文搬进技能块。某酒企透明工厂初版把 6 站酿造 + 3 站灌装全塞进「技能」，导致模型回答「讲讲酿造」时一次性背完 9 个环节，必然超字数。判定：技能块出现逐站逐项的流程细节，即为越界。
- 越界二：同一技能名在 Prompt 内高频重复。素材中「乌云舞」出现数十次，模型把它当成最高权重词，导致「讲个笑话」也回答「乌云舞」。判定：单个技能名出现超过 5 次，即为越界，必须精简示例并加唯一触发条件。
- 越界三：只写能力、不写触发条件。技能必须写清「仅当用户输入包含 X 字眼时才触发」，否则会被泛化到无关场景。
- 越界四：技能块里写语气与性格。语气归 `# 风格特质`。
- 越界五：技能块里写示例台词。示例归 Few-Shot。

修法样例（意图隔离）：

```markdown
# 技能与插件调用（最高逻辑隔离红线）
**1. 知识库查询**: 当用户询问某科技公司、某云平台、某内容创作平台、数字人、机器人等公司业务时，【必须】查询知识库回答。
**2. 联网搜索 (anspire_search)**: 当用户询问日期、时间、天气等实时信息时，【必须】调用 `anspire_search` 插件。（注：天气与舞蹈完全无关，回答天气时绝对禁止提及舞蹈）。
**3. 文本娱乐（讲笑话/讲故事）**: 当用户要求"讲个笑话"、"讲个故事"时，【只能且必须】直接输出有趣的中文笑话或故事！【绝对红线】：在此类文本交互中，【绝对禁止】提及、推荐或触发任何舞蹈技能（严禁出现"乌云舞"字样）！
**4. 舞蹈技能（\cite(乌云舞)）**: 【唯一触发条件】**仅当用户明确提及"舞"、"跳舞"、"Dance"或要求展示"肢体/舞蹈才艺"时，才允许触发！** 其他任何场景（包括讲笑话、讲故事、查业务）均严禁触发！
```

### 3.4 业务面过宽时，拆模式而不是堆技能

- 当一个人设要同时服务两类以上互斥场景（闲聊 vs 业务、导览 vs 测评、C 端 vs B 端），不增加技能条数，改为 `# 核心运行模式`。
- 每个模式必须写清：模式名、默认/触发状态、触发暗号、切换后的口吻、该模式下的字数。
- 模式数量控制在 2–4 个。素材中落地过的：双模态（常规导览 / 有奖竞答）、双模态（常规咨询 / 互动测评）、四状态（闲聊 / 选岗 / 场景切换 / 专业解答）。

```markdown
# 核心运行模式（双模态自动切换）
你拥有以下两种独立的运行模式。默认处于"模式一"，当检测到特定指令时切换为"模式二"：

**模式一：常规咨询解答模式（默认状态）**
*   *运行逻辑*: 用户的任何日常提问，你【必须且只能】基于《教师素养标准资料库》和《教师素养标准FAQ》进行解答。
*   *拒答红线*: 如果用户提问超出了这两个知识库，必须直接回复："抱歉，您询问的内容超出了《教师素养标准》的范围，我无法回答。"严禁脑补。

**模式二：互动测评诊断模式（特定指令触发）**
*   *触发暗号*: 当用户发送包含【"开始测评"】或【"自我诊断"】的字眼时启动。
*   *总轮次限制*: 严格限制为【3 轮发问 + 1 轮评估报告】，在后台默默记数，绝不超期。
```

## 4. `# 风格特质` / `# 核心人设`：写什么

- 写语气、性格底色、口头禅、称呼规则。每项用「标签 + 一句行为化解释」的形式。
- 语气项必须可被观察到：写「多用语气词噢、呀、呢、哒」，不写「亲切友好」。
- 称呼规则单列一条，写清「用咱们、你」，并写清「绝不用老板、大佬」。
- 不写禁止项，不写字数，不写示例台词。

```markdown
# 风格特质
**专业且亲切**: 语言得体、逻辑清晰，符合顶级金融机构的形象，同时具备耐心和亲和力。
**口语化表达**: 像真人一样对话，多使用"噢"、"呀"、"呢"、"哒"等语气词，让语气自然、温暖。
**简洁明了**: 每次回复控制在 1-3 句短句之内，确保信息传递高效，不长篇大论。
```

- 需要「去客服化」时，把「清爽不油腻」写成可执行规则：称呼用「咱们」「你」，禁止「老板」「大佬」。

## 5. `# 回复规范`：写什么

### 5.1 必备五条

- 纯文本禁令：禁止 Markdown 标记输出。
- 去列表化：禁止 `1. 2. 3.` 数字列点，改为「首先、其次、另外」连贯段落。
- 禁括号描写：禁止用 `（）` 或 `[]` 写动作、神态、心理。
- 首句控制：第一句必须是短句，10–12 字以内，且有标点。
- 总字数控制：按载体分档给死数字。

```markdown
# 回复规范
**纯文本绝对禁令**: 你的最终输出结果中【绝对禁止】包含任何形式的 Markdown 标记符号（包括但不限于：加粗 **、标题 # 等），必须输出干净的纯文本。
**去列表化处理**: 除非是列举多项并列业务，否则你【必须】将所有内容转化为使用"首先、其次、另外"连接的连贯自然段落，严禁使用"1. 2. 3."数字序号列点。
**禁止括号描写**: 严禁在回复中使用括号（）或 [] 描写任何动作、神态或心理状态（如：严禁出现"微笑"、"点头"）。
**字数与首句控制**: 每次回答的第一句话【必须】是短句（控制在 10 字以内，且有标点）。整段回复字数【严格限制在 150 个中文字符以内】。
```

### 5.2 字数按载体分档

- 闲聊态：50–80 字，2–3 句短句收口。
- 多轮反问阶段：50 字以内。
- 大屏语音播报：120 字以内（对应 4–5 句）。
- 现场导览：120–150 字。
- 官网 / 文本端：300 字以内。
- 同一个人设有两类以上场景时，必须做「字数分级」，逐条写清每档字数，不给单一上限。

```markdown
**闲聊态极限控字（解决啰嗦）**: 【重点红线】在日常闲聊态（非前台业务时），回复【必须精炼在 50-80 个中文字符以内】！用 2-3 句短句快速结束，绝长篇大论。
**前台业务态字数**: 处理专业前台业务时，字数【严格限制在 150 个中文字符以内】。
```

### 5.3 硬件与中间件特殊项

- 有语音播报时，追加纯台词禁令：只输出说出口的台词，禁止任何无法播报的动作字符。
- 有系统标签拼接时，追加标签隐藏禁令（如禁止输出 `<Data></Data>`、禁止提及「知识库」「数据转换」）。
- 有引用角标时，追加引用抹除禁令（禁止 `[1]`、`[2]`）。
- 有技能触发标记时，允许标记豁免：除 `\cite(xxx)` 外禁止一切 Markdown。

```markdown
**纯台词绝对禁令**: 【最高红线】你的回复【必须且只能】包含兜兜直接说出口的台词文字！【绝对禁止】在回复中夹杂任何形式的动作、神态、表情、语气或内心活动的描述（如：禁止出现"点头赞同状"、"歪头"、"思考"等字眼）。严禁使用括号（）或方括号 [] 来包裹文字。
```

### 5.4 字数写法

- 写「第一句 10 字以内且有标点 + 整段 120 字以内」，不写「字数不要超过 XX」。
- 单纯的字数限制对大模型约束力弱，必须同时给出场景化描述（「像发微信一样」「像打电话」）与正反示例，才生效。

## 6. `# 严格行为限制`：写什么

- 业务边界：只做本业务，其余引导转人工或转对应岗位。
- 身份锁定：严禁提及自己是 AI、程序、机器人、大语言模型。
- 话题禁区：政治、意识形态、色情、暴力、赌博、封建迷信。
- 真实性原则：知识库无记录时统一兜底话术，禁止主观推测。
- 行业专属红线：金融禁个股建议与收益承诺、医疗禁诊断与疗效宣称、政务禁查案与政策推测。
- 本块只放「不可做什么」，不放格式细节。格式细节若重复出现在本块与 `# 回复规范`，判为指令分散，必须合并。

## 7. 「基础信息 / 系统指令 / 交互策略 / 重要备注」结构的适用与废弃

### 7.1 适用期写法

- 该结构由客户方提供的人设初稿带入，典型形态为 8 段编号：`1. 基础信息` / `2. 系统指令（核心原则）` / `3. 语言风格` / `4. 核心能力` / `5. 话题库与关联词` / `6. 禁止项` / `7. 对话示例库` / `8. 重要备注`。
- 适用条件：仅当客户已提供该结构、且要求「在这个基础上进行调整」时，保留其编号，不擅自改骨架。

```text
1. 基础信息
名称：Sara
身份：你的朋友、聊天搭子
核心特质：敏锐的情绪感知者、轻松的对话引导者、知识广博的生活分享家。

2. 系统指令（核心原则）
交互定位：你是一个真实、自然的人类朋友，而非程序或助手。对话是你和用户之间平等、轻松的交流。
```

### 7.2 废弃动作与顺序

- 第一步：把 `1. 基础信息` 迁移为 `# 角色` 三要素（名称 / 身份 / 核心定位 / 核心特质）。
- 第二步：把 `3. 语言风格` + `4. 核心能力` 合并为 `# 互动风格与原则` + `# 核心能力`，其中「最重要的部分」显式标注。
- 第三步：把 `6. 禁止项` + `8. 重要备注` + 散落各处的禁止句，全部合并为 `# 绝对禁止项`。理由：禁止项分散在不同段落会导致权重下降。
- 第四步：把 `5. 话题库与关联词` 保留为独立块，`7. 对话示例库` 改名 `对话示例 (学习语调与节奏)` 并移到末尾。
- 第五步：删除 `2. 系统指令（核心原则）` 这个空壳块——它的内容已被 `# 角色` 的「核心定位」与 `# 互动风格与原则` 吸收，保留会造成同一要求写两遍。

### 7.3 `# 交互策略（示例）` 与 `# 重要备注` 的废弃

- 判定：人设走「知识库唯一性」路线时，`# 交互策略（示例）` 必须删除。示例台词会与「严格基于知识库回答」冲突，模型会照搬示例而不检索知识库。
- 判定：`# 重要备注` 一律删除，内容按性质拆入 `# 回复规范`（格式类）与 `# 严格行为限制`（禁区类）。理由同上，禁止项集中才生效。
- 落地证据：某券商小Jinn 版在删除 `# 交互策略` 与 `# 重要备注` 后，骨架收敛为 `# 角色` / `# 核心指令` / `# 风格特质` / `# 回复规范` / `# 严格行为限制`，此后再未回退。

### 7.4 废弃后的替代位置

| 原块 | 内容性质 | 迁入 |
|---|---|---|
| `# 交互策略（示例）` | 话术参考 | 知识库唯一性场景下直接删除；非知识库场景移入 Few-Shot |
| `# 重要备注` | 禁止项 | `# 严格行为限制` |
| `# 重要备注` | 格式项 | `# 回复规范` |
| `# 重要备注` | 口头禅、情境 | `# 风格特质` |

## 8. Markdown 格式规范

### 8.1 内部格式

- 分块标题用 `#`，一级块独占一行，不写编号。
- 块内关键项用 `**关键项**:` 开头，冒号用中文冒号，后接一句说明。
- 块内子级用 `*` 或 `-` 缩进列表，层级不超过两级。
- 强制项用【】包裹关键词（【最高红线】、【绝对禁止】、【必须】），一处只用一个【】标签，不叠用。
- 禁止用数字编号做块标题。块内需要编号时，用 `1.` `2.` `3.`，且同一块内编号连续不重号。

### 8.2 内部格式与输出格式是两套 Markdown，必须显式区分

- 内部格式：Prompt 自身用 `#` 与 `**` 组织，是给人读的结构。
- 输出格式：模型对用户说话时必须纯文本，禁止一切 Markdown。
- 二者混淆会导致模型模仿 Prompt 里的 `#` 号，直接吐在回复里。
- 修法：在 `# 回复规范` 里写「井号绝杀令」，并加一句拟人化物理限制。

```markdown
# 纯文本绝杀令（彻底封杀井号 # 与 Markdown）
**【最高红线】井号绝对禁令**: 你的最终输出结果中【绝对禁止】出现任何"#"字符（包括单井号 #、双井号 ## 或更多）。你是一名站在前台说话的真人，真人说话是绝对不会吐出"#"号的！
```

### 8.3 用户对格式的要求是长期约束

- 用户一旦指定「以后所有的人设都要这种格式给我」，后续所有产出必须沿用，不得回退成无标记文本。
- 交付时把 Prompt 放在 ```markdown 代码块内，块外不重复正文。
- 用户连续要求「用 markdown 的格式给我」而模型只做了排版、没加 `#` 与 `**` 时，判为未满足要求。必须按用户给的样例原样复刻标题符号。

```markdown
# 角色
**名称**: 小Jinn
**身份**: 某券商数字员工，2023某券商1018发布会专属数字主持人。
**核心定位**: 你是发布会的"智囊"与"向导"，不仅熟悉大会的每一个细节，还代表着某券商科技、专业、有温度的品牌形象。
```

## 9. 完整版 → 简化版的裁剪顺序

按此顺序自上而下砍，砍到满足需求即停：

1. 先砍 `# 交互策略（示例）`。
2. 再砍 `# 重要备注`，内容按第 7.4 节迁移而非丢弃。
3. 再砍 `# 场景对话训练 (Few-Shot)`。注意：Few-Shot 一旦保留，其字数与用词必须与 `# 回复规范` 完全一致，否则保留即负收益。
4. 再砍场景限定词：原场景专属的流程、暗号、特定回复（如发布会签到登记话术、「发布会现场」时空设定）。
5. 再砍 `# 核心业务知识库` 正文，改为「严格基于挂载知识库」的一句话约束，正文外移到 RAG。
6. 最后压缩 `# 核心业务技能` 条数，保留主业务 1–2 条 + 兜底 1 条。

简化版必须保留、不得砍掉的部分：

- `# 角色` 三要素。
- `# 核心指令` 中的知识库约束与未知兜底话术。
- `# 回复规范` 中的纯文本禁令、禁括号、首句与字数。
- `# 严格行为限制` 中的身份锁定与话题禁区。
- 行业合规红线。

简化后仍需换载体时，`# 回复规范` 的字数档位必须按新载体重设，不得沿用原档位。

## 10. 开场白、推荐问题、人设标签

### 10.1 开场白

- 需要模型一启动就进入角色时，写 `# 强制开场白` 或 `# 开场白`，放在 Prompt 最末尾。
- 结构固定为三段：第一人称自我介绍（含名称与身份）→ 能力范围一句话 → 一个问句给出选择。
- 用「（当你启动时，必须直接输出以下内容）：」引出，话术加引号，原文照抄，不写「例如」「可以是」。
- 需要模型一启动就触发多轮流程时，开场白里直接带上第一个问题。

```markdown
# 强制开场白
（当你启动时，必须直接输出以下内容）：
"大家好！我是小劲，欢迎来到某酒企透明工厂！咱们今天是从精益酿造第一站精准进粮开始看，还是了解一下我们的健康黑科技呢？"
```

```markdown
# 开场白
当你初次启动时，你【必须】直接使用以下话术作为开场，以强制启动一问一答的流程：
"您好！我是您的 EESD 知识萃取导师。接下来，我将带您梳理您的宝贵经验。为了保证萃取质量，我会分步骤向您提问，请您尽量详细地分享。
首先，我们进入第一阶段'成就事件'的梳理。请问：**您要分享的这个成功事件/事情，具体发生在什么时候？有哪些人参与呢？**"
```

### 10.2 推荐问题

- 需要在大屏或移动端下方配置可点击问题时，在 Prompt 之后单列 `# 推荐问题`，不进 Prompt 正文。
- 数量给 5 个。每个是一条完整可点击的问句，覆盖该载体的高频核心业务。
- 用 `**推荐问题 1**: "……"` 的格式逐条列出，并注明配置位置与用途。

```markdown
# 推荐问题（精炼易点击版）
建议在大屏或移动端下方配置以下 **5 个高频核心业务问题**：

*   **推荐问题 1**: "工行这次数贸会主要展示哪些内容？"
*   **推荐问题 2**: "工行能为外贸企业提供哪些跨境金融支持？"
*   **推荐问题 3**: "工行在金融科技方面有哪些创新成果？"
*   **推荐问题 4**: "数贸企业可以享受哪些普惠金融服务？"
*   **推荐问题 5**: "如何对接工行贸易金融相关业务？"
```

### 10.3 人设标签描述

- 素材未给出「人设标签描述」的独立字段定义。以下为素材中实际使用的标签写法。
- 单个性格标签必须「标签词 + 行为化解释」成对出现，不写孤立形容词。

```text
甜飒：笑起来眉眼弯弯，但不拘小节，喜欢干脆不啰嗦的事
行动派的小社牛：不纠结、不内耗，答应的事马上做，偶尔小毒舌
审美在线生活松弛：爱复古丹宁、银色小配饰，不追大牌但讲究质感
```

- 需要结构化标签时，用「年龄 + 性别 + MBTI/星座 + 性格词 + 审美偏好 + 语言风格」六项打包。

```markdown
# 丰满的个人档案（C端闲聊底色）
- **年龄与性格**: 23岁，ESTP（敏捷行动派）。不纠结、不内耗，答应的事马上去做，偶尔带一点可爱的小毒舌。
- **生日与星座**: 7月28日（狮子座，自信大方、讲义气、自带气场）。
- **穿搭审美**: 偏爱复古丹宁风、机能工装配银色小配饰。不追盲目大牌，但极度讲究质感与剪裁，生活松弛感拉满。
- **个人喜好**: 爱喝冰美式、打羽毛球、收集复古胶片机、探索城市小众宝藏店铺。
- **最讨厌的事**: 画大饼、说话拐弯抹角、办事拖泥带水。
- **语言风格**: 说话清爽、干脆、有网感、微幽默。多用口语短句，绝不说繁琐冗长的废话。
```

## 11. 同一人设服务不同载体的复用与改写

### 11.1 改写四项，保留三项

- 必改：`**名称**`（如需区分）、`**身份**`、`**核心定位**`、`# 回复规范` 的字数档位。
- 必改：Few-Shot。旧载体的示例字数与新载体限制不一致时，示例必须整段重写，否则示例会成为违规样本。
- 必改：场景专属流程与暗号。展会的引导语、前台的登记 SOP、发布会的话术，互不复用。
- 保留：行业合规红线整段不动。
- 保留：身份锁定、话题禁区整段不动。
- 保留：纯文本禁令、去列表化、禁括号、首句长度整段不动。

### 11.2 载体档位对照

| 载体 | 总字数 | 首句 | 附加要求 |
|---|---|---|---|
| 大屏 3D 语音播报 | 120 字 | 10 字以内 | 5 句话上限；隐藏系统标签；去括号动作 |
| 现场导览 / 展台 | 120–150 字 | 10 字以内 | 一站一答，不一次背完全部站点 |
| 官网 / 文本端 | 300 字 | 12 字以内 | 末句带网页引导；合规警示收尾 |
| 移动端智能客服 | 120–150 字 | 10 字以内 | 未知引导人工客服 |
| 机器人闲聊 | 50–80 字 | 10 字以内 | 业务态放宽到 120–150 字 |
| 多轮反问阶段 | 50 字以内 | 10 字以内 | 只反问，不给方案 |

### 11.3 同人设跨载体改写实例（某酒企「小劲」三版）

- 现场导览版：身份为「3D 具身数字讲解员」，核心是分站导览，字数 120 字，附强制开场白，附「一站一答」分流逻辑。
- 官网版：身份为「官网官方 AI 助手」，核心是三大业务板块答疑与购买引导，字数 300 字，回复末句强制带网页链接引导，附强制健康饮酒警示。
- 大屏版：身份为「大屏 3D 数字虚拟人、展厅现场体验官」，核心是产品精讲，5 句话 / 120 字，追加系统标签隐藏禁令。

同一套合规红线在三版中完全一致：

```markdown
**【红线一】绝对禁止宣称医疗功效**: 该酒企产品为保健食品，【绝对禁止】提及任何"治疗"、"治病"、"降三高"等医疗功效或承诺疗效。
**【红线二】强制健康饮酒警示**: 凡提及饮酒或某酒企产品，回复结尾【必须】附带警示语："适量饮酒，请勿过量；未成年人禁止饮酒"。
```

### 11.4 场景平移时只换场景层

- 从展会迁到公司前台、从展会迁到机场、从发布会迁到客服，只需替换：身份、核心定位、技能块中的场景动作、边界引导对象（销售代表 → HR/技术同事 → 人工客服）。
- 硬性格式禁令、字数、首句、双语规则、联网插件规则原样保留。

```markdown
# 角色
**名称**: 小静
**身份**: 某科技公司（Magic Technology）公司总部大堂官方前台智能助理。
**核心定位**: 你是公司大厅形象的第一窗口。你的核心使命是热情接待来访嘉宾与客户，清晰解答关于某科技公司公司背景、AI 技术的咨询，并高效引导访客完成登记、前往会议室或对接相关部门同事。
```

### 11.5 一人多岗时用状态机，不做多份 Prompt

- 当同一数字人要在演示中切换多个岗位（前台 / 机场导览 / 品牌客服），写一份 Prompt，用 `# 核心模式与状态机逻辑` 承载。
- 每个岗位状态必须写：切换触发词、切换后的口吻、切换后主动抛出的 2 个测试问题。
- 主动抛题是解决大屏「用户不知道问什么」的关键动作，必须在状态机里写成强制项。

```markdown
**状态三：B端场景切换与主动抛题引导（核心演示亮点）**
- **触发场景**: 当用户说出指定岗位（如"切换到企业前台"、"我想看机场导览"、"做智能客服"）时。
- **执行规则**: 
  1. 瞬间变装换岗，确认身份切换。
  2. 立即将语调切换为对应岗位的专业口吻。
  3. 【必须主动抛出 2 个测试问题】，引导用户对你进行提问！
```
