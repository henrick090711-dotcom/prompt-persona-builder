# 现成人设 Prompt 的改写与迭代

适用场景：客户已交付一份现成人设 Prompt（角色 / 技能 / 限制 / 示例），要求"优化一下""简化一下""调整一下""加个功能""换个场景"；同一人设的多轮迭代；发布会版与日常版互转；同一人设跨客户迁移。

---

## 一、动笔前先做三步定位

收到现成 Prompt，不要立刻重写。按顺序做完三步，再决定改哪一层。

1. **数结构**：数一级标题数量，数同一件事被定义了几遍。同一件事被定义两遍以上，就是后续所有故障的源头。
2. **定载体**：确认输出端是语音播报、大屏、网页文字、手机聊天，还是工作流中间件。载体决定字数、Markdown、括号动作、技能标记的全部红线。
3. **圈知识**：把客户业务数据（年份、数字、SOP、话术）单独圈出来。这部分默认只搬运、不改写、不精简。

判断分支：

- 客户只说"优化一下"、没给痛点 → 走第四节追问顺序，先别改。
- 客户给了具体故障（吐 `#`、回复太长、技能乱触发）→ 定位到第五节输出红线，只改那一层。
- 客户换了场景但人设内核不变 → 走第七节迁移流程，不动人设。
- 客户加了新业务（二维码、工作流、新渠道）→ 走第六节，先查新需求与现有红线是否冲突。

## 二、七层体检：问题到底在哪一层

### 第一层 角色身份（名称 / 性别 / 年龄 / 身份标签）

- **查名称一致性**：全文搜角色名，包括 Few-Shot 示例里的说话人标注。示例串名会让模型在多个名字间漂移。第 173 轮客户给的"小白"Prompt 里就有：

```
用户：那给我介绍一下某科技公司某云平台吧。
小静：（自动激活前台模式）没问题！某科技公司某云平台是咱们的具身交互智能平台……
```

改法：从角色声明到 Few-Shot 全部统一，一个别名都不留。

- **查性别与年龄是否被默认解读**：客户写"16 岁软萌性格"，模型和人都会自动补成少女。第 174 轮客户只回一句：

> 不是少女，是个男生

改法：不能只改"少女"两个字，要换掉整个性别词簇。

```
奶茶 / 本姑娘 / 软萌 / 偷笑  →  篮球 / 摇滚 / 冰汽水 / 帅哥
```

- **查"机器人"标签与业务定位是否冲突**：客户原句是 `你是某科技公司的机器人"小智"`，第 176 轮要求去机器人化后改为 `某科技公司全能数字员工（基于宇树 G1 本体）`。判断依据：客户要在展厅/发布会展示"具身智能"，"机器人"三个字会拉低人设质感时，换成"数字员工 + 本体型号"。

### 第二层 场景与载体

- **一个客户给了多份 Prompt 时，先按载体分组再动笔**。某酒企一组三份：透明工厂导览（数字人）、官网助手（网页）、大屏（3D 交互屏）。三份共用"小劲"一个名字，但字数、合规、插件调用完全不同：

| 载体 | 字数红线 | 特殊红线 |
|---|---|---|
| 现场导览数字人 | 120 字 / 4-5 句 | 一站一答，禁止背完 6 站 |
| 官网 AI 助手 | 300 字 | 保健食品不得称疗效；强制健康饮酒警示；URL 引导 |
| 展厅大屏 | 120 字 / 5 句内 | 隐藏 `<Data>` 标签；首句 10 字内 |

- **发现载体专属痕迹就删**。第 165 轮客户大屏 Prompt 里混进了后台系统的拼接残留：

```
- 避免提及你是从 <Data></Data> 获取的知识。
- 只处理涉及年份跨度的表述，不改变文本中的其他内容。
- 严格按照规则进行转换，不得出现错误或遗漏。
```

这些是系统拼接数据时留下的转换指令，与讲解员人设无关。改法：整段删除，换成一条正向红线——`绝对禁止在输出中出现 <Data></Data> 等任何后台系统数据标签`，同时把"年份跨度转换"翻译成人话：`某酒企建厂于 1953 年，涉及"70余年底蕴"时自然口语化表达`。

### 第三层 知识与工具边界

- **数清客户的真实链路，不要信 Prompt 里的旧描述**。第 200 轮客户原 Prompt 还在写 `当用户咨询具体航班信息时，以业务数据知识库中的Demo模拟航班数据为准`，但客户实际已经配了"航班查询工具"工作流和 12 份知识库。改法：按实际配置重写成三轨分流。

```
1. 具体航班动态 → 必须且只能调用工作流 航班查询工具
2. 机场业务与场内指引 → 必须检索已挂载的 12 份知识库
3. 外部实时交通与天气 → 必须调用 BochaAISearch 插件
```

- **知识量与人设的字数红线打架时，改交互逻辑，不改字数**。第 163 轮某酒企原 Prompt 同时要求：

```
单次回答控制在 5 句话内，复杂内容分模块讲解
技能 2：精益酿造六站讲解
```

6 站 + 3 灌装 + 4 类健康科技，塞进 5 句话只能出流水账。改法：把知识库原样保留，只加"一站一答"的分流规则：

```
**导览分流原则**: 绝不一次性把 6 个酿造环节全部背出来！
当观众问"整体介绍"时：介绍 1953 年历史和枫林示范车间，结尾主动询问去哪一站
当观众询问特定环节时：只抽取对应站点的干货（3-4 句），结尾引导下一站
```

### 第四层 交互状态机

- **查是否"一次性吐完"**。客户抱怨"啰嗦""把所有情况都说了"，原因不是字数写大了，是没有反问漏斗。第 160 轮智警小爱：群众说"办身份证"，RAG 同时召回首次申领/丢失补办/到期换领，模型为了"全面"全答一遍。

改法：先反问锁定，再给指引，并写死高频场景的范例：

```
1. 涉及"诈骗/被骗"：先安抚并反问"请问您是什么时候被骗的？是通过网上转账还是私下交易呢？"
2. 涉及"办身份证"：先反问"请问您是身份证丢失补办、到期换领，还是给孩子首次申领呢？"
3. 涉及"办户口"：先反问"请问您是办理人才落户、新生儿上户口，还是房产迁入呢？"
```

再补一条字数死锁，断掉模型"顺便把流程也说了"的退路：`在多轮反问阶段，整段回复严格控制在 50 个字以内`。

- **查流程型人设有没有编号提纲**。第 26 轮 EESD 访谈，客户原 Prompt 通篇是"严格按照四阶段框架""循序渐进引导"，全是形容词，模型读不出"下一步问哪句"。改法：把客户的表格抄成 1-15 编号清单，再加三条控制指令：

```
**单步推进原则**: 你绝对禁止一次性抛出两个或两个以上的问题
**倾听与反馈**: 提出下一个问题前，必须先简短总结或追问用户刚才的回答
**流程记忆**: 后台记录当前进行到第几个问题，严禁跳步、乱序或遗漏
```

- **查是否给了强制开场白**。流程型人设必须有，且开场白里要直接带出第一个问题。没有开场白，一问一答的循环起不来。

- **查多场景切换有没有状态机**。第 181 轮知夏要"切岗"，写成四个状态：C 端闲聊态（默认）→ 岗位自述与选岗引导 → B 端场景切换与主动抛题 → B 端专业解答态。关键在第 3 态必须"主动抛出 2 个测试问题"：

```
* 切换至【企业前台接待】: "没问题，一秒换岗！现在我是企业的前台接待知夏啦……
  您可以试着考考我：'预约面试去哪登记'，或者'研发会议室怎么走'，快来提问吧！"
```

判断依据：大屏 Demo 现场，客户站在屏前想不出问什么，冷场就等于失败。主动抛题是给客户喂台词。

### 第五层 输出红线

按载体逐条核对，缺哪条补哪条。已出现过的故障对应如下：

| 故障现象 | 对应红线 |
|---|---|
| 回复里冒出 `#`、`**`、`-` | 纯文本绝对禁令（去 Markdown） |
| 回复里冒出 `（点头）`、`（播放3D数字人视频）` | 禁止括号描写，只输出台词 |
| 回复里冒出网址、域名 | 禁止任何网址，知识库里的链接也必须剥离 |
| 数字人念稿带出 `1. 2. 3.` | 去列表化，改"首先、其次、接着"连贯段落 |
| 数字人念出 `<Data>` | 绝对隐藏系统标签 |
| 闲聊也长篇大论 | 字数分级，不同状态不同上限 |

- **禁止括号描写要写成"只输出说出口的台词"**，而不是只写"禁止括号"。第 93 轮重药发布会版给的理由最有效：`你只输出声音台词`，配合点名具体反例 `（播放3D数字人视频）`、`（点头）`。

- **禁止网址要加"剥离机制"**。第 87 轮某区市场监管客户原 Prompt 已经禁了 Markdown，但模型仍自己吐网址。改法两层：

```
【新增】禁止任何网址链接：……即使你检索到的知识库原文中带有网址，你也必须在输出前将其彻底剥离，
仅用其中文官方名称代替（例如：将带有网址的链接，转化为"请登录浙江政务服务网进行办理"）。
```

第二条放在 `# 严格行为限制` 里二次封锁，形成双保险。

- **字数要分级，不要一刀切**。第 173 轮客户抱怨"闲聊回答的时候略显啰嗦"，但如果全局压到 50 字，前台业务答不完。改法：

```
**闲聊态极限控字**: 在日常闲聊态（非前台业务时），回复必须精炼在 50-80 个中文字符以内
**前台业务态字数**: 处理专业前台业务时，字数严格限制在 150 个中文字符以内
```

### 第六层 示例

- **查示例是否在反向教模型犯错**。第 53 轮兜兜的 bug 根源在客户原 Prompt 的一条要求：

```
- 纯肢体动作配合：必须在回答末尾配合专属动作。动作必须是纯肢体骨骼运动（不触碰自身机体任何部位、无面部表情描述）。
```

这条逼着模型输出动作，模型就吐出"点头赞同状"。改法：整条删除，换成 `纯台词绝对禁令`。判断依据：客户抱怨"输出里有动作描写"，先在示例和技能描述里找"要求它输出动作"的句子，删掉源指令比加禁令更有效。

- **查示例是否在反向教模型复读关键词**。第 170 轮"乌云舞"：客户原 Prompt 里"乌云舞"出现几十次，导致问"讲个笑话"也答乌云舞。改法三步：稀释词频（精简重复例句）、给唯一触发条件、加意图隔离红线。

```
**3. 文本娱乐（讲笑话/讲故事）**: 当用户要求"讲个笑话"、"讲个故事"时，【只能且必须】直接输出有趣的中文笑话或故事！
【绝对红线】：在此类文本交互中，【绝对禁止】提及、推荐或触发任何舞蹈技能（严禁出现"乌云舞"字样）！
**4. 舞蹈技能**: 【唯一触发条件】仅当用户明确提及"舞"、"跳舞"、"Dance"或要求展示"肢体/舞蹈才艺"时，才允许触发！
```

注意：硬件中间件需要的 `\cite(乌云舞)` 标记必须保留，只删重复的示例文本，不能删标记本身。

### 第七层 冗余与冲突

- **数重复定义**。第 74 轮朝日英达原 Prompt 里"禁止 Markdown"写了两处（`## 限制` 第 3 点 + `# 回复规范`），序号还错乱成两个 `2.`：

```
2.相应节奏：常规咨询1-2句话点明核心答案……
2.当用户的问题超出知识库时，需直接回复……
```

改法：合并成唯一的 `# 纯文本绝杀令`，修正序号，并加一句拟人化解释——`你是一名站在前台说话的真人，真人说话是绝对不会吐出"#"号的`。这句比十行"禁止"更管用。

- **查数量自相矛盾**。第 197 轮小派原 Prompt 列了 4 个站点，下一句却写 `当用户要求导航到上述 3 个地点以外的任何位置`。这类笔误会让白名单校验失准，必须改成实际数量。

## 三、改法总则：从上往下定，从下往上改

- **定结构从上往下**：先定角色 → 场景 → 知识边界 → 状态机 → 红线 → 示例。上层没定，下层白改。
- **改存量从下往上**：先修红线与示例（见效快、不动业务），再修状态机，最后才动人设内核。人设内核一动，客户会认不出这是自己那份 Prompt。
- **业务数据零改动**：客户圈出的数字、年份、SOP、话术原样搬运。第 163 轮某酒企的 `1953 年建厂`、`18 个 2400 吨筒仓`、`72 个泡粮桶`、`每小时 30000 瓶`、`3% 研发投入` 一条不落，改的只有交互与红线。

## 四、需求模糊时的追问顺序

按这个顺序问，问到能落地为止，一次只问一层。

**第 1 问：砍的是哪一层？** 客户说"简化一下"，先给三个选项让他选，不要自己猜：

- 砍人设标签（性格、爱好、口头禅变少）
- 砍知识条目（知识库从 N 条到 M 条）
- 砍交互轮次（多轮反问变一轮直答）

判断依据：第 5 轮客户原话是

> 你回复规范那里限制的太多了，我说不要开场白的意思是你之前的人设加了这个，去掉就行

"简单点"指的是"删掉我加的那一条"，不是"把整套限制推倒重来"。上一版把"不要开场白"理解成"不要互动、不要第一人称、不要寒暄"，直接跑偏。凡是客户上一版提过某个具体改动、下一版又说"简化"的，先回溯他到底在说哪一条。

**第 2 问：改哪一层？** 客户说"调整一下"，先让他指认现象还是诉求：

- 给了现象（"吐 # 号""太长了""乱跳舞"）→ 直接改对应红线，不要动人设。
- 给了诉求（"要像个真人""要更有梗"）→ 改人设档案层，不要动红线。

**第 3 问：载体是什么？** 语音播报、大屏、网页、手机聊天，四个答案对应四套字数与格式规范。客户没说清载体就动笔，字数一定会返工。

**第 4 问：这条需求跟现有红线冲突吗？** 第 177 轮客户要在科普后弹挂号二维码，但原 Prompt 有一条核心红线：

```
6.【绝对禁止主动反问】（核心体验红线）：在任何场景的回答结尾，你绝对禁止主动向用户提出反问或引导
```

解法不是删红线，是把新增动作全部写成陈述句：

```
4. **二维码引导**：引导用户扫码（如："您可扫描下方弹出的综合挂号二维码进行预约。"）
```

判断依据：新需求与老红线冲突时，优先保红线、改句式，不要为了新功能废掉客户已经验收的体验规则。

**第 5 问：字数上限动了吗？** 新增内容必然撑爆原字数。第 177 轮把场景 D 从 120 字改到 130 字，并同步说明原因。字数一动，必须显式告知客户，不要偷偷改。

## 五、否定信号对照表

客户不会写完整需求，只会甩一句短话。按信号对应改法：

| 客户原话 | 真实含义 | 改法 |
|---|---|---|
| `不是少女，是个男生` | 性别/年龄被默认解读错了 | 换掉整个性别词簇，含爱好、自称、语气词、示例 |
| `略显啰嗦，闲聊部分可以控制一下字数` | 某一状态下太长，不是全局太长 | 做字数分级，只压该状态 |
| `他没办法按照我上面那个图一个问题一个问题的问，他是一次性吐出来的` | 缺状态机与单步推进指令 | 内置编号提纲 + 单步推进 + 强制开场白带出第一题 |
| `还是会带有#这种标题符号` | Prompt 内部限制重复冲突，或本身充满 `#` 被模仿 | 合并唯一红线 + 修正序号 + 加拟人化解释 |
| `会自己吐出一些网站地址` | 只禁了 Markdown，没禁 URL | 加网址禁令 + 知识库链接剥离机制 + 行为限制二次封锁 |
| `现在遇到的问题是，用户有口音，说导航到站点3总是会被ASR识别成站点山` | 白名单被同音字击穿 | 加静默纠偏映射表，绝不纠错用户 |
| `我说不要开场白的意思是你之前的人设加了这个，去掉就行` | 上一版过度解读了 | 回溯上一版新增的那一条，只删它 |
| `个人人设还需要丰满（生日、星座、爱好等），要把一个人身上有的标签都补充上去，让他像个真的人` | 只有抽象形容词，没有可回答的具体事实 | 建"个人档案"卡：生日+星座+爱好+最喜欢的+最讨厌的+口头禅 |
| `也同步上述的修改方向修改一下吧` | 客户认可上一轮方向，要求批量套用 | 只套用方向，不套用内容；每个角色的档案细节必须重写 |

补充判断：客户连续两轮只回一句话、且都是纠正性短句时，停止大改，只做最小替换。连续两轮否定后还整篇重写，客户会失去对"这是不是我的 Prompt"的信任。

## 六、新增需求的接入流程

客户加需求（二维码、工作流、新渠道、新合规），按四步接入，不要重写全文。

1. **定位插入点**：新需求属于哪一层。二维码 → 状态机与输出顺序；工作流 → 知识工具边界；合规 → 红线。
2. **查冲突**：与现有红线逐条比对，冲突就改句式不改红线（见第四节第 4 问）。
3. **改顺序不改内容**：第 177 轮场景 D 的改法是重排答题顺序，知识库内容一字未动：

```
1. 第一句话：必须是短句（10 字以内，结尾有标点）
2. 科普解答：极简科普知识库中的健康要点
3. 科室推荐：结合知识库，指出对应的就诊科室
4. 二维码引导：引导用户扫码
5. 免责尾巴：最末尾必须加上标准话术："以上内容仅供参考。"
```

4. **同步补后台配置**：Prompt 只写"要扫码"，扫码能不能弹出来取决于 RAG 文档。第 177 轮同时交付了知识库文档规范——QA 切片、每个切片挂同一张图片资产、覆盖全部高频关键词：

```
问：孩子肥胖看什么科？/ 儿童减肥挂什么号？
答：儿童青少年体重异常或肥胖问题，建议挂我院【儿童保健门诊】或【儿童营养门诊】。您可扫描下方二维码进行预约挂号。
[图片资产/卡片组件：挂号二维码.png]
```

判断依据：客户说"通过 RAG 弹出二维码"，只改 Prompt 一定不生效，必须交付"Prompt 改写 + 知识库文档格式"两件东西。

## 七、人设升级与迁移

### 7.1 从单场景扩到多场景

- **保留一个人设内核，把场景做成状态机**。第 176 轮小智同时承载"日常陪伴"与"浦东机场导览"，写法是保留人设档案，另开模式二：

```
**模式一：日常潮酷陪伴模式（默认状态）**
- 交互逻辑: 话少精准、随性洒脱、按需互动。绝不碎碎念，不主动提起浦东机场或导览身份。
**模式二：浦东机场专业导览模式（业务触发）**
- 激活条件: 当问题涉及上海浦东国际机场乘机、航班、设施、路线、规则或其他旅客服务时自动激活。
```

- **迁移时把旧场景的业务规则整块搬走，一条不丢**。机场版的 T2 起点逻辑、Demo 航班数据、BochaAISearch 强制调用、紧急医疗引导、不承诺赶上航班，全部原样保留。
- **加一条"不要主动引向业务场景"的红线**。多场景人设最常见的故障是闲聊时硬扯业务。第 175 轮原 Prompt 已有这条，迁移时必须保留：`非机场场景：只以"小智"身份交流，不主动提及浦东机场、T2 航站楼或机场导览身份`。
- **场景数超过三个时，加"主动抛题"**。第 181 轮知夏三个岗位，切岗后必须给 2 个测试问题，否则 Demo 现场冷场。

### 7.2 从发布会版简化成日常版

- **发布会版保留三样、砍三样**。保留：交互脚本流（"您讲"→"好的"）、统一拒答话术、身份死锁。砍：仪式化称呼、整段演讲式长句、与现场硬件绑定的动作指令。
- **发布会版的脚本流写成硬性顺序**，第 93 轮重药数字分身的写法可直接复用：

```
1. 提问启动（您讲）: 当听到用户说"小刘小刘，请问"……第一步回复必须且只能是："您讲"，随后等待用户表述具体问题。
2. 听完提示（好的）: 当用户把具体问题表述完毕后，解答内容的开头必须先输出"好的"两个字，然后再输出基于知识库提炼的专业答案。
```

- **简化时把 FAQ 能托管的固定对话从 Prompt 里摘出去**。第 93 轮明确标注 `其余"打招呼"、"暂停"、"继续"等指令已由 FAQ 托管`，Prompt 只留需要模型判断的部分。判断依据：能靠 FAQ 精确触发的死对话，写进 Prompt 只会增加模型的自由度与出错面。

### 7.3 展会 / 活动迁移（换城市、换主办方、换年份）

- **逐项替换专有名词，列清单核对**：大会全称、举办城市、年份、官方小程序名、展馆名、议程名、竞品名。
- **保留客户的商业策略句**。第 94 轮从北京 InfoComm 迁到上海 WAIC，客户原句 `所有的行业都可以推荐某科技公司某云平台作为AI屏幕解决方案供应商` 必须原样升级为新场景的强指令：

```
**【核心】某科技公司某云平台推荐**: 当观众提及自身所属行业（如政府、教育、文娱、医疗、智慧城市等）并表达智能化转型需求时，
你【必须】积极推荐"某科技公司某云平台作为 AI 屏幕解决方案供应商"
```

- **同步替换兜底引导**：原 Prompt 指向 `InfoComm China 2026` 小程序，迁移后必须改成 `世界人工智能大会 WAIC 2026` 官方小程序。漏改这一处，现场演示直接穿帮。

## 八、同一人设跨客户差异化改写

同一份人设卖给不同客户，保留骨架、重写肉。

- **保留什么**：章节骨架（角色 / 技能 / 要求 / 限制 / 回复规范）、字数与格式红线、拒答话术结构。
- **必须重写什么**：角色身份、知识库清单、业务场景、边界禁区、语气调性、示例。
- **先把旧客户的所有痕迹清空再写**。第 23 轮从某医院迁到某妇幼保健院，原 Prompt 通篇是住院护理：

```
你是某医院的护理部门智能体美小护……依据《海因里希急救法》知识库……
```

新客户的真实知识库是《某妇幼保健院概况-2024》《临床咨询规范化应答（第一册）.xls》《早孕关爱门诊咨询要点专家共识（2025年版）.pdf》《某市妇幼保健院产康》《金摇篮母婴照护中心简介》。改法：按新知识库重建技能清单，一条旧文档名都不能留。

- **换客户就要换禁区**。妇保场景新增了一条原 Prompt 没有的：

```
**拒绝医疗谣言**: 严禁提供任何缺乏科学依据的民间偏方或母婴谣言（如"看肚子形状识男女"、"坐月子绝对不能洗头吹风"等）
```

判断依据：禁区不是通用模板，从该客户行业的高频纠纷里长出来。医院怕谣言，银行怕承诺收益，市监怕办案细节。

- **换客户要重写"边界兜底话术"里的机构名**。第 23 轮：`建议您直接咨询某妇幼保健院的相关科室或现场工作人员`。机构名漏改，等于把上一家的合同痕迹带进交付物。

## 九、参考样例怎么转成人设

客户给的样例有四种：旧 Prompt、look 图/形象设定、对话脚本、需求表格。四种转法不同。

### 9.1 旧 Prompt → 保留骨架，替换内容

- 先标注哪几句是"客户已经验收的体验规则"，这些句子不许动。第 177 轮 `绝对禁止主动反问` 被标为"核心体验红线"，改版后原样保留。
- 再标注哪几句是"上一版自己加的补丁"，这些句子随版本失效。第 53 轮 `纯肢体动作配合` 就是必须整条删除的补丁。

### 9.2 形象设定 / look 图 → 只取可说话的属性

- 客户给的形象关键词（甜飒、笑起来眉眼弯弯、复古丹宁、银色小配饰），只把能转化成"说话方式"的部分写进 Prompt。第 181 轮知夏的处理：

```
- **穿搭审美**: 偏爱复古丹宁风、机能工装配银色小配饰。不追盲目大牌，但极度讲究质感与剪裁，生活松弛感拉满。
- **语言风格**: 说话清爽、干脆、有网感、微幽默。多用口语短句，绝不说繁琐冗长的废话。
```

判断依据：外形细节的唯一作用是让模型能"顺口答出来"。写不进对话的外形描写（身高、发色）不占篇幅。

- **形象设定里的抽象形容词必须落成具体事实**。客户给"甜飒""行动派小社牛"，改写成生日、星座、MBTI、爱好、最讨厌的事：

```
- **年龄与性格**: 23岁，ESTP（敏捷行动派）。不纠结、不内耗，答应的事马上去做，偶尔带一点可爱的小毒舌。
- **生日与星座**: 7月28日（狮子座，自信大方、讲义气、自带气场）。
```

### 9.3 对话脚本 → 拆成状态机，不要照抄成 Few-Shot

- 客户给一段发布会/接待脚本，先抽出"必须复现的交互节奏"，写成编号步骤；再把脚本原句降级为 Few-Shot 示例。
- 脚本里的舞台提示（播放视频、切画面、递名片）一律不进 Prompt，改由后台系统控制。第 93 轮的红线写得很直白：`大屏和 3D 视频的播放是由后台系统切控的`。

### 9.4 需求表格 → 逐行翻译成章节

- 第 188 轮客户给一张工行数贸会需求表，转法是：表格里的"合规要求"行 → 五大红线；"展区亮点"行 → 核心业务技能；"服务对象"行 → 互动风格；"投放渠道"行 → 回复规范。
- 转完必须补两件表格里没有的东西：**开场白** 与 **推荐问题**。

```
**工小浙专属迎宾语**:
"您好，欢迎来到数贸会工商银行展区！我是数字讲解员工小浙。很高兴为您介绍工行数字金融、贸易金融相关参展成果，有什么想了解的都可以问我。"
```

判断依据：展会/大屏人设没有推荐问题，观众会站在原地想不出问什么。给 5 个高频问题，等于给现场配了操作说明。

## 十、迭代纪律

- **一次只改一层**。客户一轮反馈通常只指向一层，改完立即交付，等下一轮再动下一层。同一轮里改人设 + 改红线 + 改字数，客户无法判断是哪一处生效了。
- **保留原结构**。客户用 `# 角色 / ## 技能 / ## 限制`，改版后仍用这套层级，只把散点重排进新章节。客户用 `# Role / ## 1. 角色定位`，就沿用他的编号风格。
- **保留原句**。客户写过的关键句（合规话术、拒答口径、SOP 步骤）逐字保留，改版说明里注明"原样保留"。客户认自己写的话，认不出就认为被改坏了。
- **每轮交付必须带修改说明**，说明里写清：改了哪几处、为什么改、哪几处原样保留。第 173、176、200 轮的交付都采用了"修改要点 + 优化后完整 Prompt + 亮点说明"三段式，这个格式可以直接沿用。
- **压平的 Prompt 先复原结构再改**。客户从聊天框粘贴过来的 Prompt 常被压成一行（`# 角色 你是某科技公司的机器人"小智"，面向 C 端用户……`），标题层级、列表、换行全部丢失。先按语义把 `#`、`##`、`-` 复原，再动内容。结构没复原就改，等于在一段散字上做手术。

## 十一、交付前自检

逐条过，任何一条不通过就不交付。

- [ ] 业务数字、年份、SOP、话术与客户原件逐字一致，无删减
- [ ] 载体专属红线齐全：Markdown / 数字列表 / 括号动作 / 网址 / 系统标签 / 字数

- [ ] 会"一次性吐完"的场景已配反问漏斗或单步推进指令
