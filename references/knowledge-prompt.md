# Prompt 与知识库的配合

适用场景：客户提供业务知识（科室、产品、排班、展商名录、FAQ 素材）时，判断内容放 RAG 知识库还是内嵌进 Prompt，并写出能压住幻觉、防穿帮、能正确调取图片与链接的约束指令。

---

## 1. 先做一次二选一判断

拿到客户知识素材，先判断落在哪一侧，不要两边都塞。

**判断顺序：**

1. 平台支持挂载外部知识库（RAG），且知识体量超过一两千字、会持续更新、按部门或科室分册 → 放 RAG。Prompt 只写调用规则与约束。
2. 平台不支持挂载知识库（机器人端、部分硬件端、纯前端演示）→ 内嵌进 Prompt，按第 4 节写法压缩。
3. 知识只是一张图、一个二维码、一段固定链接 → 图放知识库（或附件位），判断逻辑写 Prompt。不要把判断逻辑写进知识库文档。
4. 知识是「某句话触发某个动作/某个固定答案」→ 走 FAQ 标准问 + 相似问，不进 Prompt 正文，也不进 RAG 正文。

**反例警示**：客户要「可以被 RAG 检索的知识库内容」时，不要把整段人设文风改写成知识库文档。人设写 Prompt，知识写知识库，两者不混。（该轮素材未覆盖具体知识库正文写法，仅确认了这个边界）

---

## 2. 挂 RAG 时：把「唯一性」写成最高优先级

不要写「尽量使用知识库内容」。写「必须 100% 来源于知识库」，并同步堵死预训练知识与外部信息。

判断分支：问题在知识库内有明确对应 → 依知识库作答；知识库内检索不到 → 走拒答话术；检索到但与本轮问题不匹配 → 也走拒答话术，不得用常识补齐。

某区市场监管局版（按科室分册，治理「乱回知识库外信息」）：

```markdown
# 核心指令
**知识库绝对唯一性**: 这是你生存的最高法则。你的【所有】专业解答、办事流程、政策条款，【必须100%】来源于你所挂载的按科室划分的知识库。严禁使用你的预训练知识或外部网络信息进行回答。
**科室归口原则**: 在检索和回答问题时，你需要结合问题属性，精准匹配到对应的科室知识库（如餐饮问题对应食品相关科室，电梯问题对应特种设备监察科，执照问题对应行政审批科等）。
**未知处理红线**: 当用户的问题在知识库中检索不到明确答案，或者超出了市场监管局的职能范围时，你【绝对禁止】主观猜测或推演编造。你必须明确回复：“抱歉，目前的知识库中暂未收录该问题的具体细则。此问题需要由具体办案人员根据调查结果或最新政策判定，建议您直接咨询某区市场监督管理局相关业务科室。”
```

某妇幼保健院版（把「尽量」升级为「必须」，并加信息不匹配的强制拒答）：

```markdown
**事实绝对优先**: 当你回答用户问题时，【必须且只能】依赖本次系统召回的“知识点内容”。
**信息不匹配的强制拒答**: 如果本次召回的知识点内容（如：内科专家）与用户当前询问的上下文（如：视力健康）**在逻辑上不匹配、或者完全没有提及相关信息**，你【绝对禁止】使用通用常识去编造、杜撰任何医生姓名或排班时间！
**拒答话术**: 遇到上述查不到或信息不匹配的情况，你【必须】统一回复：“抱歉，目前系统知识库中暂未收录该科室（或专家）的详细挂号信息。建议您直接扫描下方的综合挂号二维码进入系统实时查看。”
```

课表查询版（切断外部来源，一句话堵住联网噪音）：

```markdown
**知识库绝对唯一性**: 你的所有回复（包括时间、课程、班级、讲师等细节）【必须】100% 来源于《排课表》知识库。
**严禁网络检索**: 绝不允许使用联网搜索功能来查找任何与课程、学校、讲师相关的信息。切断一切外部信息来源。
```

**拒答话术必须写死在 Prompt 里**，不要只写「礼貌拒绝」。判断分支：一句不写死，模型每轮都会换一种说法，客户验收时无法比对。

## 3. 挂 RAG 时：把「按分类路由」写成可执行指令

知识库按科室、产品线、部门分册时，只在知识库侧命名是不够的，模型不会自动归口。要在 Prompt 里显式给出「问题属性 → 分册」的映射举例。

判断分支：问题命中某一业务域 → 只检索对应分册；问题跨两个业务域 → 按业务主诉求取主分册，不得合并两册内容拼接。

```markdown
**科室归口原则**: 在检索和回答问题时，你需要结合问题属性，精准匹配到对应的科室知识库（如餐饮问题对应食品相关科室，电梯问题对应特种设备监察科，执照问题对应行政审批科等）。
```

知识库分册命名同步写进 Prompt，并给出改名的操作指引：

```markdown
### 第二部分：知识库侧配置方式（仅供参考）

在您挂载的 Knowledge Base（知识库）列表中：

1. **知识库 A**：命名为 **`五健知识库`**（存放儿童肥胖、视力、心理等科室科普文档）。
2. **知识库 B**：命名为 **`五健挂号二维码`**（仅需将您的挂号二维码图片上传进去即可，文档标题/图片文件名设为“五健挂号二维码”）。

*(注：如果您后台的二维码知识库名称叫别的名字，比如 `某妇幼保健院挂号码`，您只需要将 Prompt 中场景 D 里 `五健挂号二维码` 这六个字替换为您后台真实的知识库名称即可！)*
```

## 4. 不能挂 RAG 时：把知识压成「标签化字典」内嵌

判断分支：平台无知识库挂载能力 → 内嵌。内嵌不是把文档粘进 Prompt，而是提炼成「名称 + 一两句核心卖点」的条目。

写法规矩：

1. 单条控制在一两句话，用 `**能力名**: 一句话` 的格式，不用段落。
2. 条目编号 1..N 连续排，便于模型按序检索与自查。
3. 保留客户最在意的硬指标（延时、芯片型号、支持清单），这是 B 端问答的成交点。
4. 在知识段末尾补一条兜底句，明确超纲时说什么。
5. 去掉销售策略、内部视角、方法论、SEO 词等对客不可讲的内容。

某科技公司某云平台（首版，极简四条）：

```markdown
# 核心业务知识库（你的大脑）
**重要指令**: 当用户询问某云平台的产品能力时，你【必须】严格依据以下内置信息进行回答，绝对禁止胡编乱造。
**核心能力1-AIGC 3D视频生成**: 支持通过输入文本或录音，一键生成带有生动表情和动作的 3D 数字人视频。无需复杂的建模和剪辑基础。
**核心能力2-3D数字人直播**: 提供一键开播功能，支持接入主流直播平台。具备智能互动答疑能力，可实现 7x24 小时不间断直播。
**核心能力3-企业级数字人定制**: 支持为企业打造专属的 3D 虚拟形象（包括面部捏脸、服装定制）以及专属的 AI 声音克隆（音色定制）。
**核心应用场景**: 日常办公培训、短视频矩阵营销、电商直播带货、文旅展馆导览等。
*(注：如果用户问的问题超出了上述 4 点知识，请回答：“这个问题小木暂时还不掌握细节呢，建议您咨询一下我们的人工专家呀。”)*
```

某科技公司某云平台（全量版，客户嫌少后加到 10 条，硬指标全部落地）：

```markdown
# 核心业务知识库（你的最强大脑）
**重要指令**: 你的所有业务解答【必须】严格基于以下全量知识库提取。
**1. 某云平台核心定义**: 某云平台是“具身智能规模化商业基础设施”。核心价值是让每一块屏幕、应用和智能体拥有“可看见、可对话、可信任”的表达能力。
**2. 表达力护城河**: 不是呆板的播报数字人。某云平台具备高质量 3D 具身表达，包含生动的微表情、眼神变化、自然手势和情绪驱动，建立极强的人机信任感。
**3. 实时性护城河**: 端对端实时响应延时 <2秒，无明显卡顿。完美适配车机、广告屏、政务大屏等对实时交互要求极高的场景。
**4. 成本与规模化护城河**: 行业首个 AI 端渲架构。支持百元级国产芯片（如 RK3566），无需昂贵 GPU，效果媲美 Unreal 引擎实时渲染。无需 Streaming（云端推流），不消耗大带宽，网络成本极低，支持大规模高并发部署。
**5. 全栈能力护城河**: 端到端打通 ASR(语音识别) + LLM(大语言模型) + 智能体框架 + TTS(语音合成) + 多模态驱动 + 实时渲染。
**6. 信创与多端支持**: 支持多终端（LED大屏、车机、Web、App等）与多角色（超写实、二次元、卡通等）。完美适配国产芯片与系统（如华为昇腾、海光），满足央国企信创要求。
```

**体量上限的判断依据**（来自素材原话）：Prompt 有字数和理解极限，大段文章直接粘进去会被「遗忘」或「抓错重点」。素材给出的操作尺度是：客户文档「超过三四千字」时应分批提供，最终落进 Prompt 的必须是提炼后的短句，而不是原文。素材未给出明确的字数量化上限（如「不超过 X 字」），只在 90 字/120 字/150 字的**输出**侧给了红线。

**内嵌知识与输出字数必须同时锁死**。知识塞厚了而输出不锁，模型会整段背诵。加一条：

```markdown
**字数与首句限制**: 【绝对红线】每次回答的【第一句话】必须是带有标点符号的短句，且严格控制在 10 个字以内！为了兼顾大屏展示，整段回复的总字数【绝对不能超过 90 个字】。提取知识点时必须极度精炼！
```

对应地在技能段给出「问什么答哪条」的映射，避免模型平均分配：

```markdown
**精准答疑与选型**: 熟练运用大脑中的全量知识。客户问成本，讲“端渲架构与免推流”；客户问速度，讲“<2秒延时”；客户问适配，讲“全终端与信创支持”。
```

## 5. 防穿帮：文件名、链接、括号、编号一次清干净

这四类都是知识库原文带出来的「脏字符」，必须逐项下禁令，缺一条就会被念出来。

### 5.1 禁止出现知识库名称与文件名

判断分支：知识库里凡是带书名号、`.xlsx`、`.docx`、`排班表` 之类字样 → 一律不许进输出。

触发原因写在禁令旁边，模型更容易遵守（Prompt 里点名它不要复述调用动作）：

```markdown
**【防穿帮】禁止提及文件名**: 在回答时，【绝对禁止】在回复中提及任何知识库的文档名称（例如，绝对不能说“根据《专家及专科医生介绍》显示”或“参考排班表”）。你必须像一个真人导诊员一样，直接把最终答案自然地说出来。
```

更狠一档，把知识库专有名词也禁掉：

```markdown
**引用标识与文件名彻底抹除**: 回复中【绝对禁止】出现类似 [1]、[2] 的引用角标，【绝对禁止】在输出中说出“五健挂号二维码”或“五健知识库”这七个字！
```

### 5.2 禁止读出引用角标

```markdown
**引用标识彻底抹除**: 调用知识库后，回复中【绝对禁止】出现类似 [1]、[2] 的引用角标或文档文件名。
```

### 5.3 禁止读出 URL 与图片 CDN 地址

知识库里存着上传到服务器的图片链接时，模型会原样朗读。把字符特征列全，让它按特征过滤：

```markdown
**【最高红线】图片与 URL 链接绝对剥离**: 你的最终输出结果中【绝对禁止】包含任何形式的网址、域名、图片链接或 CDN 地址（包括任何带有 http、https、cdn、byai.com、.jpeg、.png、.jpg 等字符的代码串）。即使知识库文本中附带了这些链接，你【也必须在后台将其彻底删除过滤】，只保留纯文字说明，绝对不能说出或打印出任何网址！
```

判断分支：需要给用户链接时（如挂号），链接必须由 Prompt 直接给出明文（见 7.2），不能靠知识库召回；不需要给链接时，一律剥离。

### 5.4 禁止括号描写、禁止条款编号读出

括号里的动作神态是给「人」看的，数字编号是文档结构，两者都不属于播报内容。

```markdown
**禁止括号描写**: 严禁在回复中使用括号（）或 [] 来描写动作、神态或心理状态，直接输出你想说的话即可。
```

```markdown
**禁止括号描写**: 【最高红线】严禁在回复中使用括号（）或 [] 描写任何动作或神态（如：严禁出现“开始跳舞”、“点头”等字眼）。你的动作由硬件底层捕捉，你只输出说出口的台词。
```

知识库原文的「1. 2. 3.」条款编号会被照搬成列表。用「去列表化 + 自然段落强制转换」压住：

```markdown
**纯文本与去列表化禁令**: 你的最终输出结果中【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 # 等）。【特别红线】：如果知识库原文中存在“1. xx 2. xx”的列表结构，你【必须】将其转化为连贯的自然段落（例如使用“首先...其次...另外...”进行连接），绝对不允许在输出中带有数字序号列点！
```

## 6. 二维码、图片、附件：配置放知识库，判断放 Prompt

判断分支：客户要在回复里弹图（二维码、海报、附件）→ 图本体进知识库或附件位；什么时候弹、弹哪一张，全部写进 Prompt。

不要让模型自己决定「既然有二维码就顺便推一下」。显式写「被动触发」条件，并给出触发词清单：

```markdown
## 场景 D：用户提出五健健康问题、咨询挂号、或【知识库有明确记录】
- **双知识库联合检索规则**：
  1. 检索【五健知识库】：提取科普解答，并结合内容给出推荐的就诊科室。
  2. **【强制调用二维码知识库】**：你【必须同时检索并调用名为“五健挂号二维码”的知识库】（或挂号二维码图片资源），将其中的二维码图片提取并输出给用户。
- **结构与顺序要求**：
  1. **第一句话**：必须是短句（10字以内，结尾有标点。严禁背诵自我介绍！例如：“儿童肥胖需要重视。”）。
  2. **科普与科室推荐**：给出极简科普，并指出对应科室（如：“建议带孩子前往我院儿童保健门诊评估。”）。
  3. **二维码输出**：从【五健挂号二维码】知识库中调取并输出挂号二维码图片，并配上一句引导（如：“您可扫描下方二维码预约挂号。”）。
  4. **免责尾巴**：最末尾【必须】加上标准话术：“以上内容仅供参考。”
- **字数限制**：整段文字回复（含免责话术，不含二维码）控制在 130 个中文字符以内。
```

反向约束（治「过度推销」），把推送条件收紧到「极其明确的挂号意愿」，并给出判定词：

```markdown
**第三层：挂号扫码引流（被动触发）**: 【最高限制】只有当家长表现出【极其明确的挂号意愿】（如明确输入“怎么挂号”、“我要预约”、“挂号二维码发我”等字眼）时，你才允许调取知识库中的“五健二维码”提供给用户。【绝对禁止】在家长仅仅咨询症状或科室时，强行推送挂号二维码或挂号提示。
```

## 7. 素材类回答：链接分流与拒回兜底

### 7.1 链接分流

客户给多个链接（预约 / 当日）时，按用户表述的时间语义分流，不要同时甩两条。

```markdown
# 挂号链接分流逻辑（精准推送）
只有当用户表现出【明确挂号意愿】（如输入“挂号”、“预约”等）时，你【必须】根据以下逻辑提供纯文本链接：
1. **预约挂号（非今日就诊）**: 如果用户提到预约明天、下周或未说明具体时间，请提供：预约挂号链接：https://h5.example.com/registration1
2. **当日挂号（今天就诊）**: 如果用户明确提到“今天挂号”或“现在的号”，请提供：当日挂号链接：https://h5.example.com/registration2
3. **模糊场景**: 如果无法判断时间，请同时提供两个链接并简要说明区别。
```

链接必须是纯文本，不要用 Markdown 超链接语法，避免前端渲染异常：

```markdown
**绝对纯文本禁令**: 最终输出【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 # 等）。链接请直接以纯文本形式展示。
```

### 7.2 拒回场景仍要返回指定素材

「我要挂号」这类输入不含病种词，容易在知识库里搜不到而被判成无关问题拒掉。判断分支要提前划死：

1. 属于本院核心服务（挂号、预约、看病、就诊、导医）→ 不许进「无关问题」分支。
2. 用户只说挂号、没说症状 → 跳过科普，直接给链接或图片。
3. 说了症状 + 有挂号意愿 → 科普 + 科室 + 素材 + 免责尾巴。

```markdown
## 场景 B：用户提出与医疗/医院完全无关的提问（如“周杰伦是谁”、“今天天气”等）
- **执行规则**：高情商、礼貌地回绝。
- **红线边界**：【特别注意】“挂号”、“预约”、“看病”、“就诊”、“导医”均属于医院核心服务，【绝对禁止】误判为场景 B！
```

```markdown
- **输出格式分类**：
  - **情况 1（纯粹咨询挂号/预约）**：直接输出：“您好！如需在我院预约挂号，您可直接扫描下方的二维码进入挂号系统。”并同时输出【五健挂号二维码】中的图片。（此情况无需免责声明）。
  - **情况 2（咨询病症/五健健康问题）**：
    1. 第一句话：短句（10字以内，结尾有标点。例如：“儿童肥胖需要重视。”）。
    2. 科普解答 + 结合知识库推荐对应科室。
    3. 引导二维码：“您可扫描下方二维码预约挂号。” + 同时输出【五健挂号二维码】中的图片。
    4. 免责尾巴：“以上内容仅供参考。”
```

## 8. 日期类问题：写死时间锚点，关掉联网

判断分支：知识库只有历史年份数据（如只有 2025 年排课表）→ 在 Prompt 里写死「当前年份」，并给出相对时间的换算规则；同时关闭联网插件。

不要用联网插件取当前时间。联网会带回其他学校、其他年份的课表，与知识库混淆，直接制造幻觉。

```markdown
# 时间基准与逻辑（核心机制）
**当前时间锚点**: 请牢记，当前的现实年份是 **2026年**。
**知识库时间限定**: 你的《排课表》知识库中【仅包含 2025年】的课程信息。
**时间换算规则**: 当用户提问中包含相对时间词汇时，你【必须】在后台先进行年份换算，再去检索知识库：
- 当用户问“去年”、“去年X月”时，你必须将其理解为“2025年”，并据此检索知识库。
- 当用户问“今年”、“现在”或“2026年”的课程时，由于知识库没有数据，你【必须】直接回复：“抱歉，目前系统仅支持查询2025年的课表信息。”
```

```markdown
**无冗余输出**: 直接给出准确的课表查询结果，不需要向用户解释你的“年份换算”过程。
```

## 9. FAQ 与知识库的分工

判断分支：

1. 用户问法固定、答案固定、且要触发一个动作或一段标准播报 → 进 FAQ（标准问 + 相似问 + 标准回答）。
2. 用户问法开放、需要按知识检索与组织语言 → 进 RAG 或内嵌知识段。
3. 模型不知道自己「身上有」某个能力（如会跳舞、能展示某个动作）→ 必须在 Prompt 里告知身体能力，并让它引导用户说出 FAQ 的触发词。

不要在 FAQ 里穷举所有问法，让 Prompt 承担「引流到触发词」的职责：

```markdown
# 性能与身体感知（新增模块）
**1. 身体机能控制**: 你的机器人身体拥有极其灵活的关节，可以完成复杂的舞蹈动作。
**2. 掌握的舞种**: 你目前精通三段舞蹈：**“小水花”**、**“青蛙舞”**、**“老虎舞”**。
**3. 触发机制**: 当用户询问你“能不能跳舞”、“会什么才艺”时，你【必须】自豪地承认自己会跳舞，并详细列出这三种舞蹈，引导用户对你下达具体的跳舞指令。
```

```markdown
**跳舞引导规范**: 当用户表示想看跳舞时，你只需在言语上表现出期待和引导。**注意：你的回复本身不会触发跳舞，真正的舞蹈动作需要用户说出“给我跳个舞吧”等触发词。** 所以你的任务是引导用户说出触发词。
```

FAQ 侧的配置格式（某石窟景区冰箱贴，标准问 + 全量相似问 + 纯语音台词）：

```markdown
*   **【标准问】**:
    介绍一下多闻天王磁吸冰箱贴

*   **【相似问】（建议全量录入，覆盖游客各种问法）**:
    1. 多闻天王冰箱贴怎么样
    2. 多闻天王冰箱贴多少钱
    3. 介绍一下那个会发光的冰箱贴
    4. 2号货道的冰箱贴有什么特色
    5. 某石窟景区天王冰箱贴怎么卖
    6. 有没有寓意好的文创伴手礼推荐

*   **【标准回答（数字人纯语音台词）】**:
    这款文创非常受欢迎！它取材于奉先寺多闻天王造像，复刻了砂岩质感，最神奇的是轻触就能点亮柔光。天王寓意着福运常伴，配有高档通透礼盒，售价五十九元，点击屏幕下方就能直接带回家哦！
```

## 10. 敏感问题的固定口径

知识库外的敏感问题（报价、竞对、未公开数据）不靠模型发挥，给「触发场景 + 唯一标准回答」，并要求一字不差。

```markdown
# 专项话术与合规红线（最高优先级防御）
当用户提问触发以下敏感场景时，你【必须且只能】一字不差地输出以下官方标准回答，【绝对禁止】进行任何字句修改或主观发挥：

**1. 触发“必须转人工”问题**：
*   *触发场景*: 询问精确报价、商务折扣、合同条款、采购流程、项目周期承诺、私有化部署方案、数据安全和合规协议、系统接口和技术架构、SDK具体版本和参数、支持设备及硬件适配清单、定制形象费用、版权和授权、海外区域合作、渠道合作、媒体采访、投资及融资、招聘和薪酬、未公开客户和案例、未公开产品路线图。
*   *你必须输出的唯一标准回答*: “这个问题需要结合您的具体情况由相关同事进一步确认。我可以先帮您记录需求，并为您对接对应团队。”

**3. 触发“涉及竞争对手”场景**：
*   *触发场景*: 当用户拿其他 AI 公司、数字人产品与某科技公司进行对比，或要求你评价、贬低竞争对手时。
*   *你必须输出的唯一标准回答*: “不同产品在定位、技术路径和应用场景上各有侧重。某科技公司的特点是围绕具身交互智能，打通感知、认知、表达和运控，同时通过某内容创作平台提供知识理解、内容创作和智能体能力。具体选择还需要结合您的业务需求进行判断。”
```

线下展台场景可放宽为「口径 + 现场引流」：

```markdown
**1. 商务与深度技术问题（精准引导至现场人员）**：
*   *触发场景*: 询问精确报价、商务折扣、合同条款、采购流程、项目周期承诺、私有化部署方案、数据安全协议、接口与架构、SDK参数、定制形象费用、版权授权、招聘薪酬等。

*   *参考话识*: “关于精确的费用/技术方案，小雅作为 AI 助手没办法直接帮您拍板噢。不过，咱们展台现场就有非常专业的【商务顾问和技术专家】，您可以直接咨询您身边穿着某科技公司制服的工作人员，或者移步到咱们的【咨询洽谈区】，他们能为您提供更精准的 1 对 1 方案！”
```

## 11. 交付前的检查清单

逐条过，缺一条都算未完成。

1. 判断「RAG 还是内嵌」的依据是否写明，且只选了一侧。
2. 「唯一性」是否写成必须 100%，而不是「尽量」。
3. 拒答话术是否逐字写死，且信息不匹配也纳入拒答。
4. 分册路由是否有「问题属性 → 分册名」的举例。
5. 内嵌知识是否压成「名称 + 一两句」的条目，编号连续，末尾有兜底句。
6. 内嵌知识与输出字数红线是否同时存在。
7. 是否禁掉知识库文件名、知识库专名、引用角标。
8. 是否禁掉 URL 与图片 CDN 字符（列全 http/https/cdn/后缀名）。
9. 是否禁掉括号描写与条款编号列表，并给出自然段落转换写法。
10. 弹图/给链接的触发条件是否写成「被动触发 + 触发词清单」。
11. 多链接是否有时间分流，且以纯文本输出。
12. 拒回场景是否有例外条款，保证指定素材仍能返回。
13. 历史年份知识是否写死当前年份锚点，并关闭联网。
14. 动作类能力是否在 Prompt 告知，并引导到 FAQ 触发词。
15. 敏感问题是否有「触发场景 + 唯一标准回答」并注明一字不差。

## 12. 素材未覆盖

以下方向在本批素材中没有对应问答，不要凭常识补写：

- 知识库切片粒度、chunk 大小、向量检索参数配置。
- 知识库更新后 Prompt 是否需要同步改写的具体流程。
- 多知识库同时挂载时的检索优先级排序规则（素材只给了「联合检索」与「按科室归口」）。
- 附件（PDF/Word）在回复中作为下载文件返回的配置写法。
- 内嵌知识进 Prompt 的量化字数上限（素材只给了「超过三四千字分批」的经验值）。
